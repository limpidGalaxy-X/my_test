# 06 · 调试与排错手册

> 事实来源：`参考_MCP_Python_SDK_v2速查表.md`（`mcp` **2.2.0**）。
> 速查表里标 **UNVERIFIED** 的地方，本文照旧标注。
> 目标：**看到报错能立刻定位到层，而不是从头重写。**

---

## 一、先分清是哪一层出问题

MCP 的调用链有 5 层。**排查顺序永远是从最内层往外**，因为外层症状往往是内层原因的放大。

| 层 | 你会看到的症状 | 第一手排查动作 |
| --- | --- | --- |
| **① Python 层** | `ModuleNotFoundError` / `ImportError` / `SyntaxError` / 装错版本 | `.\.venv\Scripts\python.exe -c "import mcp, mcp_types; print(mcp.__file__)"`；`pip show mcp` 看版本是否 2.x |
| **② SDK 注册层** | import 期 `ValueError`（URI 参数不匹配、静态 resource 带参数）；tool 没出现在 `list_tools` 里 | 直接 `python -c "import server"`。**注册错误几乎都在 import 期就炸**，能 import 成功说明注册没大问题 |
| **③ 协议层** | JSON-RPC error（`-32601` / `-32602` / `-32603` / `-32001`）；`is_error=True`；`MCPError` | 用内存 `Client(mcp)` 打印原始结果；看服务端日志里的 error 对象 |
| **④ 传输层** | 连接失败、421、400、413、超时、`Task group is not initialized` | `curl` 手工打一次 HTTP；换 stdio 试同一个 server —— **能跑通一半就说明是传输层** |
| **⑤ Host 层** | Host 里看不到 server / 工具名不对 / Host 自己报错 | `mcp dev server.py`（Inspector）；检查 Host 的 server 配置（命令、路径、env） |

**一句话判层法**

```
python -c "import server"       失败 → ①②层
Client(mcp) 内存调用             失败 → ③层（或 ②层漏注册）
stdio 换成 streamable-http 就好了 → ④层（或 ⑤层配置）
只有某个 Host 不行为              → ⑤层
```

> 经验：**90% 的"MCP 不工作"最终落在 ① 和 ⑤** —— 装的是 v1 的 import 路径，或者 Host 配错了启动命令。
> 真正协议层的疑难杂症远比你以为的少。

## 二、报错信息 → 原因 → 解决（大表）

| # | 报错 / 症状 | 原因 | 解决 |
| --- | --- | --- | --- |
| 1 | `ModuleNotFoundError: No module named 'mcp.server.fastmcp'` | v2 已**删除** `mcp.server.fastmcp`（不是 deprecated），代码是 v1 写法 | `from mcp.server import MCPServer`，把 `FastMCP(` 全量替换为 `MCPServer(`；`mcp.server.fastmcp.*` → `mcp.server.mcpserver.*` |
| 2 | `ModuleNotFoundError: No module named 'mcp'` | 没装 / 装到了别的解释器 / venv 没激活 | 用**明确的解释器路径**：`.\.venv\Scripts\python.exe -m pip install "mcp[cli]"`；再 `-c "import mcp; print(mcp.__file__)"` |
| 3 | `ImportError: cannot import name 'FastMCP' from 'mcp.server'` | 依赖被解析到 2.x，但代码还是 `FastMCP`（v2 没有别名） | 改 `MCPServer`；暂时未迁移就先锁 `mcp>=1.28,<2` |
| 4 | `TypeError: MCPServer.__init__() got an unexpected keyword argument 'port'` | transport 参数已**搬离构造器**（`host`/`port`/`stateless_http`/`json_response`/路径/`transport_security` 都在 `run()` 与 `*_app()` 上；`mount_path=` 已删除） | `MCPServer("x")` + `mcp.run(transport="streamable-http", port=3001)`；挂载场景用 `Mount("/", app=mcp.streamable_http_app())` |
| 5 | `ValueError: Mismatch between URI parameters {...} and function parameters {...}` | resource URI 里的 `{placeholder}` 名与函数参数名不一致（**import 期**报错） | 让两边名字逐个对齐：`@mcp.resource("books://{title}")` ↔ `def book_entry(title: str)` |
| 6 | 静态 resource 带参数报错 / `ValueError`（resource 上带函数参数或 `Context`） | 静态 resource（URI 无 `{param}`）**不允许**函数参数，也**不允许** `Context` 参数（源码里显式 `ValueError`） | 要参数就把 URI 写成模板 `"books://{title}"`；要 Context 也只能用模板形式 |
| 7 | 日志里 `Context is not available outside of a request` | 在 **resource / prompt** 里写了 `ctx: Context[AppContext]`（带泛型），或 helper 函数里凭空声明 `Context` | resource / prompt 里**只能写裸 `Context`**；泛型写法 `Context[AppContext]` 只允许在 tool 里；helper 要显式传参，不能靠注入 |
| 8 | `RuntimeError: Client must be used within an async context manager` | `Client(...)` 是 `@dataclass`，**构造不等于连接**；没进 `async with` 就调用方法 | `async with Client(mcp) as client:` 之后再 `await client.call_tool(...)` |
| 9 | `RuntimeError: Task group is not initialized. Make sure to use run().` | ASGI **挂载**会让子应用 lifespan 失效；宿主 app 没跑 session manager | 宿主 lifespan 里 `async with mcp.session_manager.run(): yield`；注意 `mcp.session_manager` **只在调用过 `streamable_http_app()` 之后**才存在 |
| 10 | `TypeError: streamable_http_client() got an unexpected keyword argument 'headers'` | 该函数参数**只有** `url`、`http_client`、`terminate_on_close` | header 挂到 `httpx2.AsyncClient(headers=..., timeout=...)`，再 `streamable_http_client(url, http_client=http_client)` |
| 11 | 调用工具返回 `is_error=True`（不抛异常） | 工具内部 `raise ToolError(...)`，或调了**未知工具** | 这是**设计行为**：错误文案在 `result.content` 里给模型看。要复盘 traceback 看服务端日志 / pytest `caplog`；`Client(mcp, raise_exceptions=True)` 只把**进程内**的消毒消息换成真实异常 |
| 12 | `MCPDeprecationWarning`（`UserWarning` 子类，默认可见） | 用了 2026-07-28（SEP-2577）废弃的能力：`ctx.info()`/`ctx.debug()`/`ctx.warning()`/`ctx.error()`/`ctx.log()`、roots/sampling/协议级 logging、客户端→服务器 progress；或没设 `validate_token_resource` | 日志改标准库 `logging`；`ctx.log` 的 `message` 参数已改名 `data`、`extra` 移除；显式写 `validate_token_resource=True/False` |
| 13 | HTTP **421 Misdirected Request**（本地好、域名全挂） | 默认只接受 localhost 的 DNS-rebinding 防护 | 传 `transport_security=TransportSecuritySettings(allowed_hosts=[...], allowed_origins=[...])`；同时把 `resource_server_url` 等 URL 换成真实域名 |
| 14 | HTTP **400 Bad Request**（协议版本头相关） | 请求头 / 报文不符合协商的协议版本；客户端还会按协商版本校验入站报文 | 确认 `Mcp-Protocol-Version`；排查是不是自造报文或不合规服务器；客户端侧 `pydantic.ValidationError` 往往是**服务端报文不合规**而不是你代码错 |
| 15 | JSON-RPC **-32602**（`INVALID_PARAMS`） | 参数不符合 `input_schema`（参数名错、类型错、缺必填） | 先 `await client.list_tools()` 打印 `tool.input_schema` 对齐参数名；高层 `MCPServer` 会校验，低层 `Server` **不再校验** —— 低层要自己查 |
| 16 | 未知工具：`is_error=True` + `Unknown tool: ...` | 工具名拼错，或注册没成功（名字来自函数名，`name=` 可覆盖） | `list_tools()` 打印真实名字；检查装饰器是否真的执行到（函数是否在被 import 的模块里） |
| 17 | `stdout` 被污染导致 JSON-RPC 解析失败 | stdio 传输**独占 stdout** 传协议；你在 server 里 `print()` / 日志走了 stdout / `input()` | 见第四节三大坑：删掉 `print()`，日志配到 stderr，别用 `input()` |
| 18 | `RuntimeError: ... attached to a different loop` / 同步工具里碰事件循环对象 | v2 **同步 handler 在线程池执行**（`def` 工具不在事件循环线程上） | 需要事件循环就写成 `async def`；或别在 `def` 工具里碰事件循环绑定的对象 |
| 19 | `pydantic.ValidationError`（客户端侧） | 客户端按**协商版本**校验入站报文，服务端报文不合规（v2 新增的严格行为） | 先确认服务端 SDK 版本与协议版本；用 `mode="legacy"` 排除现代协议路径 |
| 20 | 超时错误码变成 **-32001**（`REQUEST_TIMEOUT`）而不是 `408` | v2 用 `-32001` 取代 `408`；超时改为 **float 秒** | 按新错误码匹配；`read_timeout_seconds` / `httpx2.Timeout(30.0, read=300.0)` 都用 float |
| 21 | `AttributeError: 'CallToolResult' object has no attribute 'isError'` | camelCase → snake_case（`is_error`/`input_schema`/`mime_type`/`structured_content`/`next_cursor` …） | 全量改 snake_case；自己 `model_dump()` 要协议格式时加 `by_alias=True` |
| 22 | `ImportError: cannot import name 'McpError'` | 改名 | `from mcp import MCPError`，构造 `(code, message, data)` |
| 23 | `ModuleNotFoundError: No module named 'mcp.shared.version'` | 该模块**已删除** | 改 `from mcp.types.version import LATEST_PROTOCOL_VERSION, ...` |
| 24 | `AttributeError: 'ClientRequest' object has no attribute 'root'` | `RootModel` 联合类型改成普通 union + `TypeAdapter` | 不再取 `.root`，直接当 union 用 |
| 25 | `ModuleNotFoundError: No module named 'httpx'` / `httpx2.ConnectError` 没人接 | v2 把 `httpx` + `httpx-sse` 换成 **`httpx2`** | `import httpx2`；logger 名变 `httpx2` / `httpcore2.*`；`except` 里的异常类一起改 |
| 26 | `MCPError: Redirect to ... not followed; use that URL as the endpoint if it is the intended server` | 重定向策略收紧 | 只有同 scheme/host/port 的 307/308 及同 host `http→https` 会被跟随；其他直接把目标 URL 当端点 |
| 27 | HTTP **413** | 请求体超过 `max_request_body_size`（默认 4 MiB） | 减小载荷或显式调大该参数 |
| 28 | 自定义数据"写了但读不到" | v2 **不再保留额外字段**（`extra="allow"` → 忽略） | 自定义数据放 `_meta` |
| 29 | `ImportError: cannot import name 'create_connected_server_and_client_session'` | 该 API 已删除 | 改 `async with Client(mcp, raise_exceptions=True) as c:` |
| 30 | `ModuleNotFoundError: No module named 'mcp.client.websocket'` | WebSocket transport 与 `mcp[ws]` 已删除；实验性 Tasks API（`mcp.*.experimental`）也删除 | 换 Streamable HTTP；`streamablehttp_client` → `streamable_http_client`；`get_session_id` 回调已删除（只 yield 两个流） |

## 三、五种可用的调试手段

### ① 内存 `Client(mcp)` —— 最快的第一刀

```python
import anyio
from mcp import Client
from server import mcp

async def main() -> None:
    async with Client(mcp) as client:
        result = await client.call_tool("search_books", {"query": "dune", "limit": 5})
        print(result.content)
        print(result.structured_content)

anyio.run(main)
```

- **完全不过网络、不过鉴权层**（`get_access_token()` 恒为 `None`），排除 ④⑤ 层干扰。
- 内存连接能用 → 问题在传输层或 Host 层。
- 想拿真实异常用 `Client(mcp, raise_exceptions=True)`（只对进程内连接有效）。

### ② `mcp dev` + MCP Inspector —— 看协议长什么样

```powershell
uv run mcp dev server.py
uv run mcp dev server.py --with pandas --with numpy
```

- 打开它打印的 URL；Tabs：**Tools / Resources / Resource Templates / Prompts**。
- 它通过 **stdio** 启动你的 server（与真实宿主完全一致），所以能同时验证 ④⑤ 层。
- `--with` 往环境里加包，`--with-editable .` 安装你自己的包。
- 需要 `PATH` 上有 `npx`（Inspector 是 Node 应用）。
- 排错价值：能在这里手填参数并看到原始返回 → **schema 对不对、注册成没成，一目了然**。

### ③ `mcp run --transport streamable-http` + curl / httpx 手工发 JSON-RPC

```powershell
uv run mcp run server.py --transport streamable-http
# 或直接跑：python server.py --serve 等价于 mcp.run(transport="streamable-http", port=3001)
```

```powershell
curl -i http://127.0.0.1:3001/mcp `
  -H "Content-Type: application/json" `
  -H "Accept: application/json, text/event-stream" `
  -d '{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"tools/list\"}'
```

- 价值：**绕过客户端 SDK**。如果 curl 通了而 `Client` 不通，问题在客户端侧；如果 curl 就 400/421，问题在传输层。
- `curl -i` 看状态码与响应头 —— 401/403/421/400 分得清清楚楚。
- 路径 = `streamable_http_path`（默认 **`/mcp`**）。
- 注意：`mcp run` 会 import 文件并找模块级服务器对象（`mcp`、`server` 或 `app`），
  文件里的 `if __name__ == "__main__":` **不会执行**；唯一转发给 `run()` 的选项是 `--transport`。

### ④ 日志：标准库 `logging`（stdio 下**必须写 stderr**）

```python
import logging
logger = logging.getLogger(__name__)
logger.info("searching for %r", query)
```

- **不要**用 `ctx.info()` 等 —— 已被 2026-07-28（SEP-2577）废弃，调用会发 `MCPDeprecationWarning`。
- ⚠️ 文档冲突提醒（速查表第 11 节）：mcpserver `Context` 的 API 页面 docstring 仍展示 `await ctx.info(...)`，
  而 `handlers/logging` 与 `deprecated` 页面说该能力已废弃。**以 `logging` 模块为准。**
- `MCPServer(..., log_level="INFO")` 会**立刻调用 `logging.basicConfig()`**（配置 **root logger**）——
  这会和你自己已有的 logging 配置抢方向盘，注意。
- `debug=` 传给 Starlette（HTTP 场景）。
- stdio 场景：**日志必须去 stderr**（见第四节），否则污染协议流。
- 重定向子进程 stderr：

```python
from mcp import stdio_client
Client(stdio_client(server, errlog=log_file))
```

### ⑤ pytest + `Client(mcp, raise_exceptions=True)`

```python
import pytest
from inline_snapshot import snapshot
from mcp import Client
from mcp.types import CallToolResult, TextContent

from server import mcp

@pytest.fixture
def anyio_backend():
    return "asyncio"

@pytest.fixture
async def client():
    async with Client(mcp, raise_exceptions=True) as c:
        yield c

@pytest.mark.anyio
async def test_call_add_tool(client: Client):
    result = await client.call_tool("add", {"a": 1, "b": 2})
    result.meta = None
    assert result == snapshot(
        CallToolResult(
            content=[TextContent(type="text", text="3")],
            structured_content={"result": 3},
        )
    )
```

- 开发依赖：`uv add --dev pytest inline-snapshot`。
- `pytest.mark.anyio` 由 anyio 的 pytest 插件提供；`anyio_backend` 返回 `"asyncio"`（或 `"trio"`）。
- `Client(mcp)` 是 **era-neutral**：默认协商 2026-07-28。**测 legacy 语义**（sampling / push elicitation /
  `message_handler`）要用 `mode="legacy"`，并**去掉** `raise_exceptions=True`（legacy 连接本来不消毒，
  该 flag 会把失败抛到 server task 里而不是测试里）。
- 想复盘工具异常：在结果上断言；traceback 在 **server 日志**里，pytest 的 `caplog` 能拿到。

## 四、stdio 服务器的三大坑

stdio 传输把 **stdout 当成协议通道**。任何写给 stdout 的东西都会插进 JSON-RPC 流里，
轻则解析失败，重则让 Host 直接判定 server 崩溃。**只有三个罪名，人人都犯。**

**坑 1：往 stdout `print()`**

```python
@mcp.tool()
def add(a: int, b: int) -> int:
    print("adding", a, b)      # ❌ 直接污染协议流
    return a + b
```

- 症状：Host 报 JSON 解析失败 / 连接莫名断掉；有时工具根本没响应。
- 修：删掉 `print`，改用 `logger`（且日志到 stderr）。

**坑 2：日志混进 stdout**

- 症状：只在 stdio 下出问题，`Client(mcp)` 内存连接**完全正常** —— 因为内存连接不走 stdio。
- 修：把 handler 指到 stderr：

```python
import logging
import sys

logging.basicConfig(
    level=logging.INFO,
    stream=sys.stderr,          # ✅ 关键
    format="%(asctime)s %(levelname)s %(name)s %(message)s",
)
```

- 也可重定向**子进程**的 stderr 到文件：`stdio_client(server, errlog=log_file)`。
- 想同时拿到 `[cli]` 的漂亮日志可用 `mcp[rich]`（rich 输出也走 stderr）。

**坑 3：用了 `input()`**

- `input()` 会从 **stdin** 读 —— 而 stdin 正被协议占用（Host 在往里写 JSON-RPC 帧）。
- 症状：server 卡住不返回；或把协议帧当作用户输入吃掉，之后全部请求错位。
- 修：任何交互都不要写在 server 里。需要配置就走环境变量 / `.env`（注意 **v2 不再读 `MCP_*` 与 `.env`**，
  那是 CLI / 宿主的责任），或让客户端通过 tool 参数传进来。

```python
# ❌ 永远不要
name = input("your name: ")
```

> 三坑自检一句话：**stdio server 里，除了 SDK，谁都不许碰 stdout 和 stdin。**

## 五、最小复现法

遇到疑难，**不要在你 500 行的 server 里改**。新建一个 20 行的文件，只留
**一个 `MCPServer` + 一个 tool + 一个内存 Client**，看问题是否复现：

- 复现 → 问题在这个最小例子里，继续砍（砍掉参数、砍掉类型注解、砍掉 async），直到定位。
- 不复现 → 问题在**被你砍掉的东西**里：lifespan、其他装饰器、导入顺序、传输配置、Host 配置。

**模板（`repro.py`）**

```python
"""repro.py — 最小复现模板：一个 MCPServer + 一个 tool + 一个内存 Client。"""
import anyio
from mcp.server import MCPServer
from mcp import Client

mcp = MCPServer("repro")            # 名字随意；transport 参数不在这里


@mcp.tool()
def add(a: int, b: int) -> int:
    """Add two integers."""
    return a + b


async def main() -> None:
    async with Client(mcp) as client:          # 内存连接，不过网络 / 不过鉴权
        print("tools:", [t.name for t in (await client.list_tools()).tools])
        result = await client.call_tool("add", {"a": 1, "b": 2})
        print("content:", result.content)
        print("structured_content:", result.structured_content)
        print("is_error:", result.is_error)


if __name__ == "__main__":
    anyio.run(main)
```

**逐步加变量（每次只加一个，直到复现）**

| 步骤 | 加什么 | 复现说明什么 |
| --- | --- | --- |
| 1 | 换成 `Client(mcp, raise_exceptions=True)` | 能看到 server 端被消毒的真实异常 |
| 2 | 加 `ctx: Context` 参数 | Context 注入 / 是否在 request 内 |
| 3 | 加 `lifespan=` | `lifespan_context` 相关问题（没 lifespan 时它是**空 dict，不是 None**） |
| 4 | 换成 `Client(StdioServerParameters(...))` | 差异出现在这里 → **stdio 三坑**或 env 问题 |
| 5 | 换成 `Client("http://127.0.0.1:8000/mcp")` | 差异出现在这里 → 传输层 / 421 / 400 / CORS |
| 6 | 加 `token_verifier=` + `auth=` | 401/403；注意内存连接**测不到鉴权** |
| 7 | 在 Host 里跑 | 只有这一步挂 → **⑤ Host 层**（启动命令、路径、env） |

**顺手可用的三条命令**

> 📌 下面命令里的 `.\.venv\Scripts\python.exe` 是**本课程自己的虚拟环境**
> （`E:\PyTest\learning\mcp_learning\.venv`），请在 `E:\PyTest\learning\mcp_learning\` 下执行。
```powershell
# 注册层：能 import 成功说明没有 import 期 ValueError
.\.venv\Scripts\python.exe -c "import repro; print('registered ok')"

# 版本核对
.\.venv\Scripts\python.exe -m pip show mcp

# 真实协议层（Inspector，stdio）
uv run mcp dev repro.py
```

> 最小复现的收益是**可丢弃**：`repro.py` 用完就删，不要污染你的项目结构。

## 六、自测

**1. 你在 server 里 `print("start")`，用 `Client(mcp)` 内存调用一切正常，但接进 Host 后请求全部失败。为什么内存连接测不出来？**

**2. 你的 server 在宿主的 Starlette 里 `Mount` 之后，第一个请求就报 `RuntimeError: Task group is not initialized. Make sure to use run().`。原因和修法？**

**3. 客户端调工具拿到 `is_error=True`，`content` 里是"no book titled 'X'"。这是 bug 吗？你想看 traceback 该怎么拿？**

**4. 同事的 server 本地 `python server.py` 一切正常，部署到 `mcp.example.com` 后所有请求 421。他怀疑是 token 问题。请纠正他，并给出修复方向。**

---

### 答案

**1.** 因为 `print()` 污染的是 **stdout**，而 **stdio 传输才把 stdout 当协议通道**；`Client(mcp)` 是**内存连接**，
根本不走 stdio，所以看不到这个问题（也正因如此它测不到 stdio 和鉴权层的行为）。
修法：删掉所有 `print()`；日志走标准库 `logging` 并显式 `stream=sys.stderr`；别用 `input()`（stdin 也被协议占用）。

**2.** **挂载会让子应用的 lifespan 失效**，所以 `mcp.session_manager` 的 task group 没被启动。修法：让宿主 app 自己跑：

```python
@asynccontextmanager
async def lifespan(app: Starlette) -> AsyncIterator[None]:
    async with mcp.session_manager.run():
        yield

app = Starlette(routes=[Mount("/", app=mcp.streamable_http_app())], lifespan=lifespan)
```

注意 `mcp.session_manager` **只在调用过 `streamable_http_app()` 之后**才存在，所以顺序不能颠倒。

**3.** 不是 bug，是**设计行为**：工具内部 `raise ToolError(...)` 会让调用**正常返回** `is_error=True`，
文案放在 `content` 里供**模型自己纠错**（未知工具同样是 `is_error=True` + `Unknown tool: ...`）。
只有 JSON-RPC error 才让 `Client` 抛 `MCPError`。想看 traceback：traceback 在 **server 端日志**里，
pytest 里用 `caplog` 拿；进程内连接可以 `Client(mcp, raise_exceptions=True)` 把被消毒的 `"Internal server error"`
换成真实异常（该 flag 对 tool 内异常无效，也不适用于 legacy 语义测试）。

**4.** 421 与 token 无关，是**传输安全（DNS-rebinding 防护）**：默认只接受 localhost，域名一换就全部
`421 Misdirected Request`。鉴权问题的状态码是 401（无凭据/凭据无效）和 403（缺 scope）。
修复方向：给 `run()` / `streamable_http_app()` 传
`transport_security=TransportSecuritySettings(allowed_hosts=["mcp.example.com"], allowed_origins=["https://mcp.example.com"])`，
并把 `resource_server_url` 等 URL 一并换成真实域名（否则修完 421 会接着遇到 401）。
