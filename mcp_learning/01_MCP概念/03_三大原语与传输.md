# 03 · 三大原语与传输

> 这一篇是**最实用**的一篇：决定你到底该用 Tool、Resource 还是 Prompt。
> 选错了，写出来的 Server 会很难用。

---

## 一、先记住这张表：谁来控制

| 原语 | 控制方 | 一句话 | 协议方法 |
| --- | --- | --- | --- |
| **Tools** | **模型**（Model-controlled） | 模型自己决定要不要调用的**动作** | `tools/list`、`tools/call` |
| **Resources** | **应用**（Application-controlled） | 应用决定哪些上下文贴给模型，像"文件" | `resources/list`、`resources/read`、`resources/templates/list` |
| **Prompts** | **用户**（User-controlled） | 用户主动选的**模板/工作流**，像斜杠命令 | `prompts/list`、`prompts/get` |

**记忆口诀：模型动手（Tools）、应用给料（Resources）、用户点菜（Prompts）。**

```
        用户点菜                应用给料                模型动手
          │                       │                       │
      ┌───▼────┐             ┌────▼─────┐            ┌────▼────┐
      │ Prompts│             │ Resources│            │  Tools  │
      └───┬────┘             └────┬─────┘            └────┬────┘
          │  "帮我评审这段代码"      │  "这是 main.rs 的内容"  │  "调用 add(1,2)"
          ▼                       ▼                       ▼
      渲染成对话消息            拼进上下文                执行并返回结果
```

## 二、Tools（工具）

### 定义

模型可以调用的函数。**MCP 里最重要、用得最多的原语。**

### 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `name` | ✅ | 工具名（唯一标识） |
| `title` | | 给人看的显示名 |
| `description` | | **给模型看的**，直接决定调用准确率 |
| `inputSchema` | ✅ | JSON Schema，描述参数 |
| `outputSchema` | | 结构化输出的 Schema |
| `annotations` | | 安全提示（见下） |
| `_meta` | | 扩展元数据 |

显示名优先级：`title` → `annotations.title` → `name`。

### `tools/list` 响应示例

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "tools": [{
      "name": "get_weather",
      "title": "Weather Information Provider",
      "description": "Get current weather information for a location",
      "inputSchema": {
        "type": "object",
        "properties": {
          "location": { "type": "string", "description": "City name or zip code" }
        },
        "required": ["location"]
      }
    }],
    "nextCursor": "next-page-cursor"
  }
}
```

### `tools/call` 响应：`content` + `structuredContent`

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "content": [{ "type": "text", "text": "{\"city\":\"北京\",\"temperature\":23.5}" }],
    "structuredContent": { "city": "北京", "temperature": 23.5 },
    "isError": false
  }
}
```

- `content`：**内容块数组**，必填。类型有
  `text` / `image` / `audio` / `resource_link` / `resource`（嵌入式资源）
- `structuredContent`：可选，机器可读的结构化结果
- 规范建议：**返回结构化内容的工具，同时也应把 JSON 序列化后放进一个 `TextContent`**（给不方便解析结构化的模型用）
- 有 `outputSchema` 时，返回的 `structuredContent` **必须**符合它

> ⚠️ `structuredContent` 和模型厂商的 "structured outputs" **不是一回事**，
> 前者是 MCP 的传输格式。

### 工具注解（annotations）

**全部都是"提示"，不是强制约束。** 而且规范明确要求客户端**把它们当作不可信**（除非来自可信服务器）。

| 字段 | 类型 | 默认 | 含义 |
| --- | --- | --- | --- |
| `title` | string | — | 人类可读标题 |
| `readOnlyHint` | bool | **false** | true = 不修改环境 |
| `destructiveHint` | bool | **true** | true = 可能有破坏性更新；false = 只做增量添加 |
| `idempotentHint` | bool | **false** | true = 重复调用无额外副作用 |
| `openWorldHint` | bool | **true** | true = 与开放世界交互（如联网搜索）；false = 封闭域（如本地记忆） |

⚠️ 注意默认值：`destructiveHint` 和 `openWorldHint` **默认 true**（即"不声明就当作危险"），
`readOnlyHint` / `idempotentHint` **默认 false**。

在 SDK 里：

```python
from mcp.types import ToolAnnotations

@mcp.tool(annotations=ToolAnnotations(readOnlyHint=True, openWorldHint=False))
def get_time() -> str:
    """Return the current time."""
    ...
```

## 三、Resources（资源）

### 定义

**可读取的数据**，用 URI 标识 —— 像"文件"或"REST 的 GET"。
由**应用**决定要不要把它的内容放进上下文。

### 两种形态

| 形态 | 注册方式 | 出现在哪个方法 |
| --- | --- | --- |
| **静态资源** | `@mcp.resource("config://app")` | `resources/list` |
| **资源模板** | `@mcp.resource("books://{title}")` | `resources/templates/list` |

### 字段

`Resource`：`uri`(必填)、`name`(必填)、`title`、`description`、`mimeType`、`size`、`annotations`、`_meta`
`ResourceTemplate`：`uriTemplate`(必填)、`name`、`title`、`description`、`mimeType`、`annotations`、`_meta`

### `resources/read` 示例

```json
{ "jsonrpc": "2.0", "id": 2, "method": "resources/read",
  "params": { "uri": "file:///project/src/main.rs" } }
```

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "contents": [{
      "uri": "file:///project/src/main.rs",
      "mimeType": "text/x-rust",
      "text": "fn main() {\n    println!(\"Hello world!\");\n}"
    }]
  }
}
```

内容二选一：`text`（文本）或 `blob`（**base64**，二进制）。

### URI 模板

规范只说"用 RFC 6570 URI Template"，字段是 `uriTemplate`。
**规范正文并没有列出允许哪些运算符**（网上很多说法是不准确的）。

实践中的约定（也是 SDK 的实现）：

| 写法 | 含义 |
| --- | --- |
| `books://{title}` | 单个路径变量，函数必须有同名参数 `title` |
| `file:///{path}` | 官方示例中出现的唯一形式 |

在 SDK 里，**URI 里的占位符名必须和函数参数名完全一致**，否则**导入时就报错**：

```python
@mcp.resource("books://{title}")
def book_entry(title: str) -> str:      # 参数名必须叫 title
    """The catalog entry for one book."""
    return f"{title} ..."
```

### 资源注解（Annotations）

| 字段 | 说明 |
| --- | --- |
| `audience` | `"user"` / `"assistant"`，给谁看 |
| `priority` | `0.0` ~ `1.0`，1 = 最重要（近乎必需），0 = 最不重要 |
| `lastModified` | ISO 8601 时间戳，如 `2025-01-12T15:00:58Z` |

### 订阅变更（2025-06-18）

```
client ── resources/subscribe {uri} ──► server
server ── notifications/resources/updated {uri} ──► client
client ── resources/unsubscribe {uri} ──► server
```
> 2026-07-28 起被 `subscriptions/listen` 取代。

## 四、Prompts（提示词）

### 定义

**用户主动选择**的模板/工作流，通常渲染成 Host 界面里的斜杠命令或按钮。

### 字段

- `Prompt`：`name`(必填)、`title`、`description`、`arguments`
- `PromptArgument`：`name`(必填)、`title`、`description`、`required`
- `PromptMessage`：`role`(`user`/`assistant`)、`content`（ContentBlock）
- `GetPromptResult`：`description?`、`messages`(必填)

### `prompts/get` 示例

```json
{ "jsonrpc": "2.0", "id": 2, "method": "prompts/get",
  "params": { "name": "code_review",
              "arguments": { "code": "def hello():\n    print('world')" } } }
```

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "description": "Code review prompt",
    "messages": [{
      "role": "user",
      "content": { "type": "text", "text": "Please review this Python code:\ndef hello():\n    print('world')" }
    }]
  }
}
```

注意：**Prompts 的参数只是扁平的命名字符串列表**，没有 JSON Schema 校验。
缺必填参数会导致整个请求失败。

在 SDK 里返回 `str` 表示一条 user 消息；返回 `list[Message]` 表示多轮对话。

## 五、三个原语怎么选？（决策清单）

| 你的需求 | 用哪个 | 为什么 |
| --- | --- | --- |
| 查询数据库、调用 API、写文件、算数 | **Tool** | 模型要主动执行动作 |
| 提供一份文档/配置/Schema 让模型参考 | **Resource** | 是"数据"，由应用决定贴不贴 |
| 提供一套可复用的提问模板/工作流 | **Prompt** | 用户主动触发 |
| 既想能查、又想被当作上下文引用 | **两个都做** | 同一份数据，Tool 查询 + Resource 暴露 |
| 想给模型"记忆" | **Tool**（写）+ **Resource**（读） | 写入是动作，读出是数据 |

**一句话判断法**：**这个操作会改变外部世界吗？**
会 → Tool；不会、只是把数据拿出来 → Resource；只是生成一段话给模型 → Prompt。

## 六、客户端的三个原语（反向能力）

Server 也可以向 Client 请求东西（2025-06-18 时代）：

| 原语 | 方法 | 用途 | 状态 |
| --- | --- | --- | --- |
| **Roots** | `roots/list` | 告诉 Server 可操作的目录/URI 边界 | 2026-07-28 **已废弃** |
| **Sampling** | `sampling/createMessage` | 借用 Host 的 LLM 生成内容（保持模型无关） | 2026-07-28 **已废弃** |
| **Elicitation** | `elicitation/create` | 向用户追问补充信息或确认 | 仍然活跃 |

### Sampling 示例（Server → Client）

```json
{ "jsonrpc": "2.0", "id": 1, "method": "sampling/createMessage",
  "params": {
    "messages": [{ "role": "user", "content": { "type": "text", "text": "What is the capital of France?" } }],
    "modelPreferences": { "hints": [{ "name": "claude-3-sonnet" }], "intelligencePriority": 0.8 },
    "systemPrompt": "You are a helpful assistant.",
    "maxTokens": 100
  } }
```

规范硬性要求：**始终应该有人类在环，且能拒绝 sampling 请求。**

### Elicitation 示例

```json
{ "jsonrpc": "2.0", "id": 1, "method": "elicitation/create",
  "params": {
    "message": "Please provide your GitHub username",
    "requestedSchema": { "type": "object", "properties": { "name": { "type": "string" } },
                         "required": ["name"] }
  } }
```

```json
{ "jsonrpc": "2.0", "id": 1, "result": { "action": "accept", "content": { "name": "octocat" } } }
```

- `action`：`accept` / `decline` / `cancel`
- `requestedSchema` 是**受限子集**：只能顶层属性，不能嵌套
- 规范硬性要求：**服务器 MUST NOT 用 elicitation 索取敏感信息**

## 七、传输方式：stdio vs Streamable HTTP

### stdio（标准输入输出）

Client 把 Server 作为**子进程**启动，通过它的 stdin/stdout 收发消息。

| 项 | 规则 |
| --- | --- |
| 分帧 | **按换行分隔**，消息内不能有内嵌换行 |
| stdout | **只能**写 MCP 消息；日志**必须**写 stderr |
| stdin | Client **只能**写 MCP 消息 |
| 会话 | 无（进程本身就是会话边界） |
| 认证 | **不应**用 OAuth，改从环境变量取凭据 |

### Streamable HTTP

Server 是一个**独立进程**，通过 HTTP 通信。

| 项 | 规则 |
| --- | --- |
| 端点 | 单一 MCP endpoint（2025-06-18 要求同时支持 POST 和 GET；2026-07-28 移除 GET） |
| 请求 | 每个消息一个 POST，body 是单条 request/notification/response |
| 响应 | `application/json`（单对象）或 `text/event-stream`（SSE 流） |
| Accept 头 | Client **必须**同时列 `application/json` 和 `text/event-stream` |
| 会话 | 通过 `Mcp-Session-Id` 响应头分配（2026-07-28 移除） |
| 版本头 | `MCP-Protocol-Version: 2025-06-18` |
| 认证 | `Authorization: Bearer <token>`，遵循 OAuth 2.1 |

### 对比表

| 维度 | stdio | Streamable HTTP |
| --- | --- | --- |
| 形态 | 子进程 | 独立服务 |
| 部署 | 只能本机 | 可远程、可水平扩展 |
| 延迟 | 低 | 略高 |
| 权限 | 与 Client 同权限 | 可隔离 |
| 认证 | 环境变量 | OAuth 2.1 |
| 适用 | 本地工具、文件操作、开发调试 | 云端服务、多人共享、需要网关/可观测 |
| 生态 | 简单 | 可复用负载均衡、鉴权网关、监控 |

### SSE 的演进（容易搞混）

| 规范版本 | 传输 |
| --- | --- |
| 2024-11-05 | HTTP + SSE（两个端点：SSE 端点 + POST 端点） |
| 2025-03-26 起 | **Streamable HTTP** 取代之 |
| 2025-06-18 | 要求 `MCP-Protocol-Version` 头 |
| 2025-11-25 | Server 可随时断开以支持轮询；无效 `Origin` 必须回 403 |
| 2026-07-28 | 移除 GET 端点、移除协议级会话、移除 SSE 续传，改用 `subscriptions/listen` |

> 旧的 **HTTP+SSE 传输已废弃**，新项目别再用了。

### 安全要求

- Server **必须**校验 `Origin`（防 DNS rebinding）
- 本地服务**应该**只绑 `127.0.0.1`
- **应该**实现认证

## 八、其他实用能力

| 能力 | 方法/字段 | 说明 |
| --- | --- | --- |
| **进度** | 请求里带 `_meta.progressToken`；通知 `notifications/progress` | `progress` 必须**递增**；完成后必须停止发 |
| **取消** | `notifications/cancelled`，字段 `requestId`、`reason?` | `initialize` **不能**被取消 |
| **日志** | `logging/setLevel` + `notifications/message` | 8 个级别：debug/info/notice/warning/error/critical/alert/emergency |
| **分页** | 请求 `params.cursor` → 响应 `result.nextCursor` | 只有 list 类方法支持；cursor 是**不透明**令牌，不能解析、不能跨会话保存 |
| **补全** | `completion/complete` | 参数自动补全，最多返回 100 个值 |
| **ping** | `ping` | 保活（2026-07-28 移除） |

进度通知示例：

```json
{ "jsonrpc": "2.0", "method": "notifications/progress",
  "params": { "progressToken": "abc123", "progress": 50, "total": 100,
              "message": "Reticulating splines..." } }
```
