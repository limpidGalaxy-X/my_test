| 项目 | 要求 | 本机情况 |
| --- | --- | --- |
| Python | **3.10+**（SDK v2 硬性要求） | 3.14.7 ✔ |

## 2. 安装

本课程自带虚拟环境 `E:\PyTest\learning\mcp_learning\.venv`，直接用它：

```powershell
cd E:\PyTest\learning\mcp_learning

# 安装（含命令行工具）
.\.venv\Scripts\python.exe -m pip install "mcp[cli]"

# 以后跑示例都用这个解释器
.\.venv\Scripts\python.exe "02_SDK基础\02_最小服务器.py"
```

如果你更喜欢 `uv`：

```powershell
uv add "mcp[cli]"
uv run --with "mcp[cli]" mcp version      # 不想装进项目的一次性用法
```

## 4. 安装失败怎么办

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `No module named 'mcp'` | 用错了解释器 | 显式用 `.\.venv\Scripts\python.exe`，别用系统 `python` |
| `No module named 'mcp.server.fastmcp'` | 装成了 v2 但代码是 v1 写法 | 改 `MCPServer`，或锁 `mcp<2` |
| `ModuleNotFoundError: mcp.server.mcpserver` | 装成了 v1 但代码是 v2 写法 | `pip install -U "mcp>=2.2"` |
| `ERROR: Could not install ... Permission denied` | 沙箱/杀软拦截临时目录 | 指定临时目录：`$env:TEMP="E:\PyTest\.piptmp"; $env:TMP=$env:TEMP` 后重装 |
| 需要 `npx` 才能用 Inspector | `mcp dev` 会拉起 Node 版 Inspector | 装 Node.js，或改用内存自测（本目录的示例都支持） |

## 5. 目录约定

本目录的每个示例都是"**一个文件 = 一个完整可跑的服务器**"：

```python
# 顶部：定义服务器与工具（可以被别的文件 import）
mcp = MCPServer("Demo")

@mcp.tool()
def add(a: int, b: int) -> int: ...

# 底部：两种运行方式
if __name__ == "__main__":
    if "--serve" in sys.argv:
        mcp.run()                 # 真实启动（stdio，阻塞）
    else:
        asyncio.run(demo())       # 内存自测（不阻塞，直接看结果）
```

**为什么要这样设计？**
因为初学者最常见的卡点是："我写了 server.py，然后呢？"
`mcp.run()` 会阻塞并等待标准输入上的 JSON-RPC 报文，直接运行它只会看到一片空白。
先用内存 `Client(mcp)` 自测，能立刻看到「工具被调用了、返回值是什么」。

---

## 6. 三种运行方式的区别

| 方式 | 命令 | 用途 |
| --- | --- | --- |
| 内存连接 | `python x.py`（本目录的自测模式） | 开发调试、单元测试。不经过任何传输层 |
| stdio | `python x.py --serve` 或 `mcp run x.py` | 给本机 Host（Claude Desktop 等）用 |
| Streamable HTTP | `mcp run x.py --transport streamable-http` | 部署给远程/多客户端用，默认 `http://127.0.0.1:8000/mcp` |
