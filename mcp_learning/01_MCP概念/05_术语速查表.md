# 05 · 术语速查表

> 看官方文档时**随手查**的一篇。术语全部取自 `参考_规范逐字摘要.md`，
> 没有素材依据的说法不收录。
> 「出现位置」列写的是**规范页面路径**（相对 `https://modelcontextprotocol.io/specification/<版本>/`）
> 或本系列文件。

**怎么用**：先在下面的大表里定位词条，不确定的多半是「容易搞混的 6 组概念」里的，
最后一节给了这些组的一对一辨析和官方文档入口。

## 一、角色与架构

| 英文术语 | 中文 | 一句话解释 | 出现位置 |
| --- | --- | --- | --- |
| Host | 宿主（应用） | 用户直接使用的 AI 应用，创建并管理多个 Client，负责安全策略、用户同意与 LLM 协调 | `architecture`；`02_架构与协议基础.md` |
| Client | 客户端 | Host 内部为**某一个** Server 建立的连接，与 Server 是 **1:1** 关系 | `architecture`；`02` |
| Server | 服务端 | 通过 MCP 原语对外暴露能力的程序，可以是本地进程也可以是远程服务 | `architecture`；`03_三大原语与传输.md` |
| Primitive | 原语 | 协议规定的能力类别：Tools / Resources / Prompts（服务端）与 Roots / Sampling / Elicitation（客户端） | `architecture`；`03` |
| Model-controlled | 模型控制 | 由**模型**决定是否调用 —— 这就是 Tools | `architecture` 控制层级表 |
| Application-controlled | 应用控制 | 由**宿主应用**决定是否贴进上下文 —— 这就是 Resources | 同上 |
| User-controlled | 用户控制 | 由**用户**主动选择触发 —— 这就是 Prompts | 同上 |
| Capability Negotiation | 能力协商 | 双方声明各自支持的能力，且**只能使用协商成功的能力** | `basic/lifecycle`；`02` |
| 1:1 relationship | 一对一关系 | `each client having a 1:1 relationship with a particular server` | `architecture` |
| MCP Host（文档版定义） | —— | `The AI application that coordinates and manages one or multiple MCP clients` | `/docs/learn/architecture` |
| Server feature | 服务端特性 | Server 提供的：Resources / Prompts / Tools / Logging / Completions | `architecture` 拓扑图注 |
| Client feature | 客户端特性 | Client 提供的：Roots / Sampling / Elicitation（后两者 2026-07-28 已废弃） | `architecture`；`03` |

## 二、协议与消息

| 英文术语 | 中文 | 一句话解释 | 出现位置 |
| --- | --- | --- | --- |
| JSON-RPC 2.0 | —— | 所有 MCP 消息**必须**遵循的底层消息格式 | `basic` |
| Request | 请求 | 需要回复的消息，含 `id` + `method` + 可选 `params` | `basic`；`02` |
| Response | 响应 | 与请求同 `id`，`result` 与 `error` **必须**二选一（不可同时出现） | `basic`；`02` |
| Notification | 通知 | 单向消息，**不含 `id`**，接收方 **MUST NOT** 响应 | `basic`；`02` |
| `id` | 请求标识 | string 或 integer；**MUST NOT** 为 `null`；同一 session 内不可重复使用 | `basic` |
| `method` | 方法名 | 形如 `类别/动作`（`tools/call`）；反向请求用单数名词（`roots/list`） | `02` |
| `result` / `error` | 结果 / 错误 | 响应里二者**必须**恰好有一个 | `basic` |
| `initialize` | 初始化握手 | Legacy 时代建立会话的**第一个**请求，携带 `protocolVersion` / `capabilities` / `clientInfo` | `basic/lifecycle` |
| `notifications/initialized` | 初始化完成通知 | Client 告知 Server 握手完成，Server 收此通知前不得发除 `ping`/logging 外的请求 | `basic/lifecycle` |
| `protocolVersion` | 协议版本 | `initialize` 请求与响应中都有；版本不匹配时的协商依据 | `basic/lifecycle` |
| `capabilities` | 能力 | ClientCapabilities / ServerCapabilities，握手时交换 | `basic/lifecycle` |
| `clientInfo` | 客户端身份 | `Implementation` 对象：`name` 必填，`title`/`version` 可选 | `basic/lifecycle` |
| `serverInfo` | 服务端身份 | 同上，Server 侧 | `basic/lifecycle` |
| `Implementation` | 实现信息 | `clientInfo` 与 `serverInfo` 的共同类型 | `basic/lifecycle` |
| `instructions` | 使用指引 | Server 给 Client 的**自然语言**使用说明（`server/discover` 里也有） | `basic/lifecycle`；`server/discover` |
| `_meta` | 元数据字段 | MCP 保留的附加元数据槽位；保留键的值 **MUST NOT** 做任何假设 | `basic#_meta` |
| `_meta.progressToken` | 进度令牌 | `ProgressToken = string \| number`，必须在所有活跃请求间唯一 | `basic/utilities/progress` |
| `cursor` / `nextCursor` | 分页游标 | 请求带 `params.cursor`，响应回 `result.nextCursor`；**不透明令牌** | `server/utilities/pagination` |
| `ping` | 保活 | 双向可用，接收方 **MUST** 迅速返回空响应；**2026-07-28 已移除** | `basic/utilities/ping` |
| `completion/complete` | 参数补全 | 为 prompt 参数或 resource URI 模板参数做自动补全，最多返回 100 个值 | `server/utilities/completion` |
| `logging/setLevel` | 设置日志级别 | Server 能力 `logging` 下的请求方法；**2026-07-28 已移除** | `server/utilities/logging` |
| `notifications/message` | 日志通知 | Server 发结构化日志；`level` 取 RFC 5424 的 8 个级别 | `server/utilities/logging` |
| `notifications/progress` | 进度通知 | `progress` **MUST** 递增；完成后**必须停止**发送 | `basic/utilities/progress` |
| `notifications/cancelled` | 取消通知 | 双向；`initialize` **MUST NOT** 被 client 取消 | `basic/utilities/cancellation` |
| `server/discover` | 服务端发现 | 2026-07-28 新增，servers **MUST** 实现，用来宣告支持的版本、能力与身份 | `server/discover`；`06` |
| `subscriptions/listen` | 订阅监听 | 2026-07-28 新增，单条长驻 POST 响应流，取代 GET SSE 与 `resources/subscribe` | `basic/patterns/subscriptions`；`06` |
| `resultType` | 结果类型 | 2026-07-28 起所有结果的**必填**字段：`"complete"` 或 `"input_required"` | `06` |
| `inputRequests` / `inputResponses` | 输入请求 / 输入响应 | MRTR 的两个字段：Server 在结果里"要输入"，Client 重试时"给输入" | `basic/patterns/mrtr`；`06` |
| MRTR | 多轮往返请求 | Multi Round-Trip Requests，取代 Server 主动发请求的旧模式 | `basic/patterns/mrtr`；`06` |
| JSON-RPC batching | 批处理 | **2025-06-18 起不支持**（changelog 第 1 条：`Remove support for JSON-RPC batching`） | `changelog` 2025-06-18 |
| Protocol Error | 协议错误 | 走 JSON-RPC `error` 对象的错误（未知工具、参数非法、服务器错误） | `server/tools`；`02` |

## 三、服务端原语

| 英文术语 | 中文 | 一句话解释 | 出现位置 |
| --- | --- | --- | --- |
| Tool | 工具 | 模型可调用的函数，**MCP 里最重要、用得最多**的原语 | `server/tools`；`03` |
| `tools/list` | 列出工具 | 唯一的工具发现方法，支持分页与 `listChanged` | `server/tools` |
| `tools/call` | 调用工具 | 执行一个工具，**不支持分页** | `server/tools` |
| `notifications/tools/list_changed` | 工具列表变更 | 需要 `tools.listChanged: true` 能力声明 | `server/tools` |
| `inputSchema` | 入参 Schema | JSON Schema，定义工具参数 | `server/tools`；`03` |
| `outputSchema` | 出参 Schema | 可选；提供后 `structuredContent` **MUST** 符合它 | `server/tools`；`03` |
| `content` | 内容块数组 | `CallToolResult` 的**必填**字段，承载非结构化结果 | `server/tools`；`03` |
| `structuredContent` | 结构化内容 | 机器可读的任意 JSON 对象；与模型厂商的 "structured outputs" **无关** | `server/tools`；`03` |
| ContentBlock | 内容块 | `TextContent \| ImageContent \| AudioContent \| ResourceLink \| EmbeddedResource` | `server/tools` schema |
| TextContent | 文本内容 | `{"type":"text","text":"..."}` | `server/tools` |
| ImageContent | 图像内容 | `{"type":"image","data":"<base64>","mimeType":"image/png"}` | `server/tools` |
| AudioContent | 音频内容 | `{"type":"audio","data":"<base64>","mimeType":"audio/wav"}` | `server/tools` |
| ResourceLink | 资源链接 | `{"type":"resource_link","uri":...}`，指向一个 Resource，可被订阅或读取 | `server/tools` |
| EmbeddedResource | 内嵌资源 | `{"type":"resource","resource":{...}}`，内容直接内联 | `server/tools`；`server/prompts` |
| `isError` | 错误标志 | 正常 result 里表达"工具执行失败"的通道；未设置时视为 `false` | `server/tools`；`02` |
| Tool Execution Error | 工具执行错误 | 用 `isError: true` 表达（API 失败、业务逻辑错误）；**输入校验错误也应走这条** | `server/tools`；`02` |
| `annotations` | 注解 | 工具行为提示的容器；**全部都是 hint**，且**必须视为不可信** | `server/tools`；`04` |
| `readOnlyHint` | 只读提示 | `If true, the tool does not modify its environment.` **默认 `false`** | `server/tools`；`03` |
| `destructiveHint` | 破坏性提示 | `If true, the tool may perform destructive updates...` **默认 `true`** | `server/tools`；`03` |
| `idempotentHint` | 幂等提示 | 重复调用同参数无额外副作用；**默认 `false`** | `server/tools`；`03` |
| `openWorldHint` | 开放世界提示 | true = 与开放外部实体交互（如联网搜索）；**默认 `true`** | `server/tools`；`03` |
| Trusted server | 可信服务端 | **唯一**可以采信其工具注解的来源 | `server/tools`；`04` |
| Resource | 资源 | 用 URI 标识的**可读取数据**，由应用决定是否贴进上下文 | `server/resources`；`03` |
| ResourceTemplate | 资源模板 | 参数化的 Resource，字段为 `uriTemplate` | `server/resources`；`03` |
| `uriTemplate` | URI 模板 | 格式为 RFC 6570 `uri-template`；**规范未列出允许哪些表达式运算符**（UNVERIFIED） | `server/resources`；`03` |
| `mimeType` | MIME 类型 | Resource / 内容块的媒体类型 | `server/resources` |
| `blob` | 二进制内容 | `resources/read` 结果中与 `text` 二选一，**base64** 编码 | `server/resources`；`03` |
| `size` | 字节数 | Resource 的**原始**内容字节数（base64 / 分词之前） | `server/resources` |
| `annotations.audience` | 受众 | 数组，取值 `"user"` / `"assistant"` | `server/resources`；`03` |
| `annotations.priority` | 优先级 | 0.0–1.0；1 = 最重要（近乎必需），0 = 最不重要 | `server/resources`；`03` |
| `annotations.lastModified` | 最后修改时间 | ISO 8601 时间戳，如 `2025-01-12T15:00:58Z` | `server/resources`；`03` |
| `resources/list` | 列出资源 | 支持分页与 `listChanged` | `server/resources` |
| `resources/read` | 读取资源 | **不支持分页**；返回 `contents` 数组 | `server/resources` |
| `resources/templates/list` | 列出模板 | 结果字段名为 `resourceTemplates` | `server/resources` |
| `resources/subscribe` / `resources/unsubscribe` | 订阅 / 退订 | 按 URI 订阅变更；**2026-07-28 被 `subscriptions/listen` 取代** | `server/resources`；`06` |
| `notifications/resources/updated` | 资源已更新 | 需要 `resources.subscribe: true` | `server/resources` |
| `notifications/resources/list_changed` | 资源列表变更 | 需要 `resources.listChanged: true` | `server/resources` |
| `listChanged` | 列表变更子能力 | prompts / resources / tools 三者都有 | `basic/lifecycle` |
| `subscribe` | 订阅子能力 | **仅 resources 有** | `basic/lifecycle` |
| Prompt | 提示词模板 | **用户主动选择**的模板/工作流，像斜杠命令 | `server/prompts`；`03` |
| PromptArgument | 提示词参数 | `name`(必填)、`title`、`description`、`required`；**没有 JSON Schema 校验** | `server/prompts`；`03` |
| PromptMessage | 提示词消息 | `role`（`user`/`assistant`）+ `content`（ContentBlock） | `server/prompts`；`03` |
| `prompts/list` | 列出提示词 | 支持分页与 `listChanged` | `server/prompts` |
| `prompts/get` | 获取提示词 | 返回 `messages`；**不支持分页**；缺必填参数返回 `-32602` | `server/prompts` |
| `notifications/prompts/list_changed` | 提示词列表变更 | 需要 `prompts.listChanged: true` | `server/prompts` |

## 四、客户端原语

| 英文术语 | 中文 | 一句话解释 | 出现位置 |
| --- | --- | --- | --- |
| Roots | 根目录边界 | 让 Server 知道可操作的 filesystem/URI 边界 | `client/roots`；`03` |
| `roots/list` | 列出根目录 | **Server → Client** 的请求；client 不支持时返回 `-32601` | `client/roots` |
| `notifications/roots/list_changed` | 根目录变更 | `"roots": {"listChanged": true}`；**2026-07-28 已移除** | `client/roots`；`06` |
| Root | 根目录条目 | `uri`（**MUST** 是 `file://` URI）+ 可选 `name` | `client/roots` |
| Sampling | 采样 | Server 借用宿主 LLM 完成一次生成，保持模型无关 | `client/sampling`；`03` |
| `sampling/createMessage` | 创建消息 | Server → Client；`maxTokens` **必填** | `client/sampling`；`03` |
| `ModelPreferences` | 模型偏好 | `hints` + `costPriority` / `speedPriority` / `intelligencePriority`（0–1） | `client/sampling` |
| `includeContext` | 上下文范围 | `"none" \| "thisServer" \| "allServers"`；后两者 deprecated 于 2025-11-25 | `client/sampling`；`06` |
| `stopReason` | 停止原因 | `"endTurn" \| "stopSequence" \| "maxTokens" \| string` | `client/sampling` |
| Elicitation | 询问 | Server 向用户索取补充信息或确认操作 | `client/elicitation`；`03` |
| `elicitation/create` | 创建询问 | Server → Client；**Server MUST NOT 用它索取敏感信息** | `client/elicitation`；`03` |
| `requestedSchema` | 请求 Schema | **受限 JSON Schema 子集**：只能顶层属性、不允许嵌套 | `client/elicitation`；`03` |
| `action` | 用户动作 | `"accept" \| "decline" \| "cancel"`；`content` 仅在 `accept` 时出现 | `client/elicitation` |
| Human in the loop | 人在环 | `there SHOULD always be a human in the loop with the ability to deny...` | `server/tools`；`client/sampling`；`04` |

## 五、传输与会话

| 英文术语 | 中文 | 一句话解释 | 出现位置 |
| --- | --- | --- | --- |
| stdio | 标准输入输出 | Client 把 Server 作为**子进程**启动，按**换行**分帧，日志只能写 `stderr` | `basic/transports`；`03` |
| Streamable HTTP | 可流式 HTTP | Server 是独立进程；单一 MCP endpoint，POST 收发，响应可为 JSON 或 SSE 流 | `basic/transports`；`03` |
| HTTP+SSE | HTTP + SSE 传输 | `2024-11-05` 的旧传输（SSE 端点 + POST 端点），**已废弃** | `changelog`；`03` |
| SSE / `text/event-stream` | 服务器发送事件 | 2026-07-28 起**只作为某个请求的响应流**，不再有独立 GET 事件流 | `basic/transports`；`03` |
| `Mcp-Session-Id` | 会话 ID | Streamable HTTP 上的协议级会话标识；**2026-07-28 已移除** | `basic/transports`；`06` |
| `MCP-Protocol-Version` | 协议版本头 | 使用 HTTP 时 client **MUST** 在所有后续请求上携带 | `basic/transports`；`02` |
| `Last-Event-ID` | 断线续传头 | SSE 事件的续传机制；**2026-07-28 已移除**（连 event ID 一起） | `basic/transports`；`06` |
| `Origin` | 来源头 | Server **MUST** 校验以防 DNS rebinding；无效时 **MUST** 返回 403 | `basic/transports`；`04` |
| `Accept` | 接受类型 | client **MUST** 同时列出 `application/json` 与 `text/event-stream` | `basic/transports` |
| `202 Accepted` | 已接受 | POST body 是 response/notification 时的正常返回，无 body | `basic/transports` |
| `405 Method Not Allowed` | 方法不允许 | 不支持 GET 流时返回；或表示不允许 client 用 DELETE 终止会话 | `basic/transports` |
| `Mcp-Method` / `Mcp-Name` | —— | 2026-07-28 起 Streamable HTTP POST **必须**携带的头 | `changelog`；`06` |
| `x-mcp-header` / `Mcp-Param-{Name}` | 参数镜像头 | 把工具参数镜像成 HTTP 头，便于网关路由与限流 | `changelog`；`06` |
| `ttlMs` / `cacheScope` | 缓存提示 | 2026-07-28 起 list/read 类结果新增的**必填**缓存字段（`CacheableResult`） | `changelog`；`06` |
| MCP endpoint | MCP 端点 | Streamable HTTP 的单一入口 URL，如 `https://example.com/mcp` | `basic/transports` |
| page size | 页大小 | 由 server 决定；`clients MUST NOT assume a fixed page size` | `server/utilities/pagination` |
| Opaque token | 不透明令牌 | cursor 的用法约束：不解析、不修改、**不跨会话持久化** | `server/utilities/pagination` |

## 六、安全与授权

| 英文术语 | 中文 | 一句话解释 | 出现位置 |
| --- | --- | --- | --- |
| OAuth 2.1 | —— | MCP 授权的基础（draft-ietf-oauth-v2-1-13） | `basic/authorization`；`04` |
| resource server | 资源服务器 | **MCP server 扮演的角色** | `basic/authorization`；`04` |
| authorization server | 授权服务器 | 签发 access token 的一方；**MCP server MUST 只接受它签发的 token** | `basic/authorization`；`04` |
| PKCE | 授权码交换证明密钥 | MCP clients **MUST** implement PKCE（OAuth 2.1 §7.5.2） | `basic/authorization`；`04` |
| RFC 8707 / Resource Indicators | 资源指示器 | client **MUST** 在授权请求与 token 请求都带 `resource` 参数，标识目标 MCP server | `basic/authorization`；`04` |
| RFC 9728 / Protected Resource Metadata | 受保护资源元数据 | `/.well-known/oauth-protected-resource`，从中取 `authorization_servers` | `basic/authorization`；`04` |
| RFC 8414 / AS Metadata | 授权服务器元数据 | `/.well-known/oauth-authorization-server` 发现端点 | `basic/authorization`；`04` |
| RFC 7591 / DCR（Dynamic Client Registration） | 动态客户端注册 | **deprecated 于 2026-07-28**，迁移到 Client ID Metadata Documents | `deprecated`；`06` |
| Client ID Metadata Documents | 客户端 ID 元数据文档 | 2025-11-25 引入的**推荐**注册机制，取代 DCR | `changelog`；`06` |
| `WWW-Authenticate` | 认证质询头 | 401 响应里携带 `resource_metadata` 与可选 `scope="..."` | `basic/authorization`；`04` |
| `resource_metadata` | 资源元数据 URL | 从 401 质询指向受保护资源元数据文档 | `basic/authorization` |
| scope | 权限范围 | 最小化起步 + 增量提升；server 端仍须自行判定授权 | `security_best_practices`；`04` |
| Token Passthrough | Token 透传 | **反模式，被明确禁止**：把非本 server 签发的 token 转发出去 | `security_best_practices`；`04` |
| Confused Deputy | 混淆代理 | 静态 client ID 的 proxy 无法区分调用方，导致用户身份被冒用 | `security_best_practices`；`04` |
| SSRF | 服务端请求伪造 | 恶意 server 用 URL 把 client 指向内网 / 云元数据端点 | `security_best_practices`；`04` |
| Session Hijacking | 会话劫持 | 偷到 session ID 即接管；**server MUST NOT use sessions for authentication** | `security_best_practices`；`04` |
| DNS rebinding | DNS 重绑定 | 通过 `Origin` 校验与只绑 `127.0.0.1` 缓解 | `basic/transports`；`04` |
| `redirect_uri` | 重定向地址 | **MUST** 精确字符串匹配（不做前缀/通配/子域） | `security_best_practices`；`04` |
| `state` | 状态参数 | **MUST** 密码学随机、单次使用、短过期；**且只有在同意后才设置** | `security_best_practices`；`04` |
| `__Host-` consent cookie | 同意 Cookie | **MUST** 用 `__Host-` 前缀 + `Secure`/`HttpOnly`/`SameSite=Lax`，并绑定 `client_id` | `security_best_practices`；`04` |
| audience | 受众 | Server **MUST** 校验 token 是为它自己签发的 | `basic/authorization`；`04` |
| `iss`（RFC 9207） | 签发者 | AS **SHOULD** 在授权响应中包含，client **MUST** 校验 | `changelog` 2026-07-28；`06` |
| Path traversal | 路径穿越 | Clients **MUST** validate all root URIs to prevent it | `client/roots`；`04` |
| Prompt Injection | 提示注入 | **官方规范正文未使用该术语、无专章**（UNVERIFIED 作为官方命名） | `04` 第六节 |

## 八、容易搞混的 6 组概念

### 1. Host vs Client

| | Host | Client |
| --- | --- | --- |
| 是什么 | 用户用的那个**应用** | Host 内部的一条**连接** |
| 数量 | 1 个 | N 个（每个 Server 一个） |
| 职责 | 安全策略、用户同意、授权决策、上下文聚合、协调 LLM 与采样 | 协议协商、消息路由、维护订阅与通知、隔离不同 Server |

> 记住 **Host : Client : Server = 1 : N : N**。
> "Client 是连接，不是应用" —— 搞错这一点，你会以为 Client 该管 UI。

### 2. Tool vs Resource vs Prompt

| | Tool | Resource | Prompt |
| --- | --- | --- | --- |
| 控制方 | **模型** | **应用** | **用户** |
| 会不会改外部世界 | **会** | 不会（只是读数据） | 不会（只是生成消息） |
| 典型形态 | API 调用、写文件 | 文件内容、git 历史 | 斜杠命令、菜单项 |
| 发现方法 | `tools/list` | `resources/list` / `resources/templates/list` | `prompts/list` |
| 执行/读取 | `tools/call` | `resources/read` | `prompts/get` |

判断法：**这个操作会改变外部世界吗？** 会 → Tool；不会但要拿出数据 → Resource；只是拼一段话给模型 → Prompt。
完整决策清单见 `03_三大原语与传输.md` 第五节。

### 3. `content` vs `structuredContent`

| | `content` | `structuredContent` |
| --- | --- | --- |
| 必填 | ✅ 必填 | 可选 |
| 类型 | `ContentBlock[]`（text/image/audio/resource_link/resource） | 任意 JSON 对象 |
| 给谁看 | 模型（也可能是人） | 程序（Client 代码） |
| 与 `outputSchema` 关系 | 无 | 有 `outputSchema` 时**必须**符合它 |

关键坑：`structuredContent` **不是**模型厂商的 "structured outputs"（见 `03`）。
另外规范建议：返回结构化内容的工具，**同时也应把 JSON 序列化后放进一个 `TextContent`**（向后兼容）。

### 4. JSON-RPC error vs `isError: true`

| | JSON-RPC `error` 对象 | `result.isError: true` |
| --- | --- | --- |
| 通道 | 协议错误 | 工具执行错误 |
| 触发场景 | 未知工具、参数格式非法、服务器内部错误 | API 失败、输入数据无效、业务规则不满足 |
| 模型看得到吗 | **基本看不到** | **看得到**（文本在 `content` 里） |
| 能不能自我纠正 | 不能 | **能** |

2025-11-25 起明确：**输入校验错误应作为 Tool Execution Errors 返回**，而不是 Protocol Errors ——
因为那是唯一能让模型读到错误并重试的通道。详见 `02_架构与协议基础.md` 第六节。

### 5. stdio vs Streamable HTTP

| 维度 | stdio | Streamable HTTP |
| --- | --- | --- |
| 形态 | Client 启动的子进程 | 独立进程 / 远程服务 |
| 端点 | 无网络端点 | 单一 MCP endpoint |
| 会话 | 无（进程即会话边界） | `Mcp-Session-Id`（2026-07-28 移除） |
| 认证 | **SHOULD NOT** 走 OAuth，从环境取凭据 | **SHOULD** 遵循 OAuth 2.1，`Authorization: Bearer` |
| 日志 | 只能写 `stderr` | 无 stdout 概念，用 `notifications/message` |
| 典型场景 | 本地工具、文件系统、数据库 | 云端 SaaS、多 Client、需要网关与可观测 |

**最容易踩的坑**：stdio 下往 **stdout** 打印任何非 MCP 内容，都会**破坏协议流**（`server MUST NOT write any non-MCP message to stdout`）。

### 6. Modern vs Legacy（规范的正式定义，逐字）

> - **Modern**：把版本、身份、能力作为**逐请求元数据**传递的协议版本（`2026-07-28` 及以后）。
> - **Legacy**：用 `initialize` 握手建立会话的协议版本（`2025-11-25` 及以前）—— **`2025-06-18` 属于 Legacy**。
> - **Dual-era**：同时支持两者的实现。
>
> There is no negotiation handshake. Every request carries its protocol version, and the server accepts or rejects each request independently.

**兼容矩阵（结论）**：

| 组合 | 结果 |
| --- | --- |
| Modern ↔ Modern | ✅ 可用 |
| Modern client ↔ Legacy server | ❌ **失败** |
| Legacy client ↔ Modern server | ❌ **失败** |
| Dual-era ↔ 任一 | ✅ 可用（自己探测） |

> 没有"向前回退"机制。这就是为什么 Python SDK v2 默认 `mode="auto"`（先探后回退）。
> 完整版本演进见 `06_规范版本演进_2026-07-28.md`。
