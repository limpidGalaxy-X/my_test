# 05 · v1 → v2 迁移对照

> ⚠️ **先看这条，能省你半天**：`pip install mcp` **现在装的是 2.x**。
> 如果你的老项目还没迁移，请立刻在依赖里加上界：
>
> ```
> mcp>=1.28,<2
> ```
>
> 官方原文："Since `pip install mcp` now installs 2.x, keep a `<2` upper bound on your requirement
> (for example `mcp>=1.28,<2`) until you've migrated."
>
> 不加的后果：某天 CI 重新解析依赖，你的 `FastMCP` 一夜之间变成 `ModuleNotFoundError`。
> 1.x 仍在 `v1.x` 分支接收关键 bug / 安全修复（1.x 最新为 `1.30.0`），文档在 https://py.sdk.modelcontextprotocol.io/v1/ —— 但迁移是迟早的事。

本文事实来源：`参考_MCP_Python_SDK_v2速查表.md`（抓取日期 2026-09-10，对应 `mcp` **2.2.0**）；速查表里标了 **UNVERIFIED** 的地方，本文照旧标注。

---

## 一、最大的变更：`FastMCP` → `MCPServer`

| | v1 | v2 |
| --- | --- | --- |
| 类名 | `FastMCP` | **`MCPServer`** |
| 模块 | `mcp.server.fastmcp.*` | **`mcp.server.mcpserver.*`** |
| 导入 | `from mcp.server.fastmcp import FastMCP` | `from mcp.server import MCPServer` |
| 是否保留别名 | — | **没有别名**。旧路径是**删除**，不是 deprecated |
| 默认服务器名 | `FastMCP` | **`"mcp-server"`**（`name or "mcp-server"`） |
| version 默认值 | — | **空字符串** |

- `from mcp import MCPServer` **不存在**。文档原文 Tip："The two halves of the SDK have two import paths:
  `from mcp import Client` and `from mcp.server import MCPServer`. There is no `from mcp import MCPServer`."
- `mcp.server.__init__` 的 `__all__`（源码核实）= `["CacheHint", "Server", "ServerRequestContext", "MCPServer", "NotificationOptions", "InitializationOptions"]`

### v1 写法 vs v2 写法（并排对照）

**① 服务器定义**

```python
# ── v1 ──                                        # ── v2 ──
from mcp.server.fastmcp import FastMCP            from mcp.server import MCPServer
mcp = FastMCP("Bookshop", port=9000)              mcp = MCPServer("Bookshop")
                                                  # transport 参数不在构造器；端口在 run()/streamable_http_app()：
                                                  # mcp.run(transport="streamable-http", port=3001)
```

**② tool / resource / prompt 装饰器**（装饰器没改名，但**参数名**换了一批）

```python
# ── v1 ──                                        # ── v2 ──
from mcp.types import ToolAnnotations             from mcp.types import ToolAnnotations
@mcp.tool()                                       @mcp.tool(
def search(q: str) -> str:                            title="Search the catalog",
    """Search."""                                     annotations=ToolAnnotations(read_only_hint=True,
    return f"found {q}"                                                       open_world_hint=False))
@mcp.resource("config://app")                     def search(q: str) -> str:
def get_config() -> str: ...                          """Search."""
@mcp.prompt()                                         return f"found {q}"
def recommend(genre: str) -> str: ...
                                                  @mcp.resource("config://app", mime_type="text/plain")
                                                  def get_config() -> str: ...
                                                  @mcp.prompt(title="Recommend a book")
                                                  def recommend(genre: str) -> str: ...
```

静态 resource 的约束在 v2 是**硬报错**（见第 6 条）。

**③ Context 用法**

```python
# ── v1 ──                                        # ── v2 ──
from mcp.server.fastmcp import Context, FastMCP   from mcp.server import MCPServer
                                                  from mcp.server.mcpserver import Context  # 导入路径变了
@mcp.tool()                                       import logging
async def work(ctx: Context) -> str:              logger = logging.getLogger(__name__)
    await ctx.info("start")
    await ctx.report_progress(50, 100)            @mcp.tool()
    server = ctx.fastmcp                          async def work(ctx: Context) -> str:
    return "ok"                                       logger.info("start")   # ctx.info() 已废弃(SEP-2577)
                                                      await ctx.report_progress(50, 100)
                                                      server = ctx.mcp_server   # ctx.fastmcp → ctx.mcp_server
                                                      return "ok"
```

- `get_context()` **已删除** → 改为在函数签名里声明 `ctx: Context` 参数（类型注解即注入，**参数名任意**）。
- 工具里写 `ctx: Context[AppContext]` 可拿到 `lifespan_context` 的类型；**resource / prompt 里只能写裸 `Context`**，否则每次调用失败，日志：`Context is not available outside of a request`。
- `ctx.info()` / `ctx.debug()` / `ctx.warning()` / `ctx.error()` / `ctx.log()` 已被 2026-07-28 规范废弃（SEP-2577），调用会发 `MCPDeprecationWarning`。⚠️ 速查表第 11 节记录**文档内部冲突**：mcpserver `Context` 的 API 页面 docstring 仍展示 `await ctx.info(...)`，而 `handlers/logging` 与 `deprecated` 页面明确说该能力已废弃 —— **以 `logging` 模块为准**。
- MIGRATION 另记：`Context` 日志的 `message` 参数改名为 `data`，`extra` 被移除。

**④ `run()` 调用**

```python
# ── v1 ──                                        # ── v2 ──
if __name__ == "__main__":                        if __name__ == "__main__":
    mcp.run()             # stdio                     mcp.run()                     # 默认 stdio
    # 端口靠构造器里的 port=                          # mcp.run(transport="streamable-http", port=3001)
                                                      # mcp.run(transport="sse")      # 已被取代，仅为兼容
```

`run(transport=...)` 只认三个值：**`"stdio"`（默认）、`"streamable-http"`、`"sse"`**。
`run()` 必须放在 `if __name__ == "__main__":` 里 —— 所有加载方式都会 import 这个文件。

**⑤ 客户端连接**

```python
# ── v1 ──
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

async with stdio_client(params) as (read, write):
    async with ClientSession(read, write) as session:
        await session.initialize()
        tools = await session.list_tools()
```

```python
# ── v2 ──
from mcp import Client, StdioServerParameters

server = StdioServerParameters(command="uv", args=["run", "server.py"], env={"API_KEY": "secret"})

async with Client(server) as client:                                # stdio 子进程，一步到位
    result = await client.list_tools()
    print([tool.name for tool in result.tools])

async with Client(mcp) as client:                                   # 内存（测试 / 嵌入）
    result = await client.call_tool("search_books", {"query": "dune", "limit": 5})

async with Client("http://localhost:8000/mcp") as client:           # Streamable HTTP
    print(client.server_info)
```

- v2 的 `Client(...)` 是 `@dataclass`，**构造不等于连接**；没进 `async with` 就用会报
  `RuntimeError: Client must be used within an async context manager`。
- `streamable_http_client` 的参数**只有** `url`、`http_client`、`terminate_on_close`；传 `headers=` 会 `TypeError`。低层逃生口仍在：`client.session`。

**⑥ 测试写法**：v1 的 `create_connected_server_and_client_session()` **已删除** → 用 `Client(mcp)`（`raise_exceptions=True` 只对**进程内**连接有效）。

```python
# ── v1 ──
from mcp.shared.memory import create_connected_server_and_client_session
async with create_connected_server_and_client_session(mcp._mcp_server) as session: ...
```

```python
# ── v2 ──
import pytest
from mcp import Client

@pytest.fixture
async def client():
    async with Client(mcp, raise_exceptions=True) as c:
        yield c
```

## 二、18 条破坏性变更逐条解释（你会看到什么错误、怎么修）

> 每条三段：**改了什么 / 典型报错 / 怎么改**；序号与速查表第 9 节一致。

**1. `FastMCP` → `MCPServer`，模块 `mcp.server.fastmcp.*` → `mcp.server.mcpserver.*`**
- 报错：`ModuleNotFoundError: No module named 'mcp.server.fastmcp'`；或 `ImportError: cannot import name 'FastMCP' from 'mcp.server'`。
- 改：`from mcp.server import MCPServer`，把 `FastMCP(` 全局替换成 `MCPServer(`。

**2. 字段 camelCase → snake_case**
- 报错：`AttributeError: 'CallToolResult' object has no attribute 'isError'`；pydantic 侧 `ValidationError: Extra inputs are not permitted`（手写旧字段名的 dict 去构造模型时）。
- 改：见第三节完整对照表。线缆 JSON **仍是 camelCase**，自己 `model_dump()` 要加 `by_alias=True`。

**3. `McpError` → `MCPError`**
- 报错：`ImportError: cannot import name 'McpError' from 'mcp'`。
- 改：`from mcp import MCPError`，构造器直接 `(code, message, data)`。⚠️ 语义坑：`MCPError` 在 tool 里抛出会变成 **JSON-RPC error**（模型看不到）；`ToolError` 才是 `is_error=True` 结果。
**4. `mcp.types` 迁到独立包 `mcp-types`**：`import mcp.types as types` **照旧能用**（永久别名，同一对象），所以不报错；但 `mcp.shared.version` 用不了 —— `ModuleNotFoundError: No module named 'mcp.shared.version'`。改：协议版本常量从 `mcp.types.version` 导入（见第五节）。

**5. 协议版本常量语义变更**：**静默行为变化**（无报错）—— `if version == LATEST_PROTOCOL_VERSION` 之类的判断逻辑直接错。`LATEST_PROTOCOL_VERSION` 已从 `"2025-11-25"` 变为 `"2026-07-28"`；`SUPPORTED_PROTOCOL_VERSIONS` 废弃；新增 7 个名字（见第五节）。

**6. transport 参数搬离构造器**
- 报错：`TypeError: MCPServer.__init__() got an unexpected keyword argument 'port'`（`host=` / `mount_path=` 同理；`mount_path=` 是**删除**）。
- 改：`host` / `port` / `stateless_http` / `json_response` / 路径 / `transport_security` 全部搬到 `run()` 与 `streamable_http_app()`。

**7. 低层 `Server` 重建**
- 报错：`AttributeError: 'Server' object has no attribute 'request_context'`；`AttributeError: ... 'request_handlers'`；`AttributeError: ... '_handle_list_tools'`。
- 改：装饰器 `@server.list_tools()` 等 → 构造参数 `on_list_tools=`、`on_call_tool=` …；handler 形状统一为 `async (ctx: ServerRequestContext, params) -> Result`；`request_handlers` / `notification_handlers` 字典删除 → 用 `add_request_handler` / `get_request_handler(method)`；`_handle_*` 删除 → 用 `middleware`。`request_ctx` ContextVar 删除。

**8. 低层自动包装移除**：handler 返回 list/dict/`Iterable[ReadResourceContents]` 不再被自动包装；参数 schema **不再校验**（脏数据直接进 handler，报错点后移）。tool handler 里抛普通异常不再变成 `CallToolResult(is_error=True)`，而是 **JSON-RPC error**（客户端侧 `Client` 抛 `MCPError`，模型看不到你的错误文案）。改：低层要自己组装返回值；想给模型看的错误必须显式返回 `is_error=True` 的结果（高层 `MCPServer` + `ToolError` 仍是 `is_error=True`）。

**9. `mcp.types` 移除的别名**：`ImportError: cannot import name 'Content' from 'mcp.types'`（`ResourceReference`、`Cursor`、`ClientRequestType` 同理）。改：`Content`→`ContentBlock`、`ResourceReference`→`ResourceTemplateReference`、`Cursor`→`str`、`ClientRequestType`→`ClientRequest`；`TaskExecutionMode` / `TASK_*` 删除。

**10. `RootModel` 联合类型 → 普通 union + `TypeAdapter`**：`AttributeError: 'ClientRequest' object has no attribute 'root'`。改：`ClientRequest` / `ServerRequest` / `ClientNotification` / `ServerNotification` / `ClientResult` / `ServerResult` / `JSONRPCMessage` 不再有 `.root`，直接当普通 union 处理（必要时用 `TypeAdapter`）。

**11. resource URI 由 `AnyUrl` 变 `str`**：报 `TypeError`（把 `AnyUrl` 对象塞进只收 `str` 的地方）；或 `str(resource.uri)` 产生**不同**的字符串（v2 不再规范化 URI）。改：`Resource.uri`、`ReadResourceRequestParams.uri`、`ResourceContents.uri` 等都是 `str`；`read_resource()` 只收 `str`。别再依赖自动规范化。

**12. 额外字段不再保留**：`extra="allow"` → **忽略**，你在自己扩展字段里塞的上下文数据会**静默消失**。改：自定义数据放 `_meta`。

**13. `create_connected_server_and_client_session` 删除**：`ImportError: cannot import name 'create_connected_server_and_client_session' from 'mcp.shared.memory'`。改：`async with Client(mcp, raise_exceptions=True) as c:`。

**14. 同步 handler 在线程池执行 + Context 相关收缩**
- 现象：`def` 工具不再阻塞事件循环，但**也不在事件循环线程上** —— 在里面碰事件循环绑定的对象（如某些 anyio 原语）会炸；报错 `RuntimeError: ... attached to a different loop`、`AttributeError: 'Context' object has no attribute 'client_id'`。
- 改：`Context` 泛型参数从 3 个减到 2 个（`Context[LifespanContextT, RequestT]`）；`RequestContext` 拆成 `ClientRequestContext` / `ServerRequestContext`；`ctx.fastmcp`→`ctx.mcp_server`；`get_context()`、`ProgressContext`/`progress()` 上下文管理器、`Context.client_id` 全部删除。

**15. roots / sampling / 协议级 logging 废弃；`ping` 移除**：调用废弃项发 `MCPDeprecationWarning`（`UserWarning` 子类，**默认可见**）；`client.send_ping()` 在现代连接上被服务端答 `Method not found`。改：roots / sampling / 协议级 logging 按 2026-07-28（SEP-2577）迁移；客户端→服务器 progress 废弃；`subscriptions/listen` 取代独立 GET 流与 `resources/subscribe`（`client.subscribe_resource(uri)` 在 2026-07-28 线上返回 `-32601`）。

**16. `httpx` + `httpx-sse` → `httpx2`**：报 `ModuleNotFoundError: No module named 'httpx'`（v2 环境里只剩 `httpx2`），或 `AttributeError: module 'httpx2' has no attribute 'Client'`。改：`import httpx2`；TLS 走系统信任库 `truststore`；logger 名变 `httpx2` / `httpcore2.*`；异常类型变 `httpx2.ConnectError` 等 —— **你的 `except httpx.ConnectError` 要一起改**。

**17. WebSocket transport 与 `mcp[ws]` 删除；实验性 Tasks API 删除；`streamablehttp_client` 删除**：报 `ModuleNotFoundError: No module named 'mcp.client.websocket'`、`ImportError: cannot import name 'streamablehttp_client'`、`mcp.*.experimental` 导入失败。改：用 Streamable HTTP；`streamablehttp_client` → `streamable_http_client`；`get_session_id` 回调删除（现在只 yield 两个流）。⚠️ 容易忽略的 `TypeError: streamable_http_client() got an unexpected keyword argument 'headers'` —— headers 要挂在 `httpx2.AsyncClient` 上。

**18. 客户端默认 `mode='auto'` + 严格校验**：客户端先发 `server/discover`，随后**按协商版本校验入站报文** —— 不合规的服务器会让你在客户端侧炸（`pydantic.ValidationError`）；超时错误码从 `408` 变成 **`-32001`（`REQUEST_TIMEOUT`）**。改：`ConnectMode = Literal['legacy', 'auto'] | str`，默认 `"auto"`；`mode="legacy"` 强制 initialize 握手（可用 server→client 推送：sampling / push elicitation / `message_handler`）；`mode="2026-07-28"` 直接采用（零协商，但 `server_info` 为 `None`），配合 `prior_discover=client.session.discover_result` 可零往返拿回身份。`cursor` 从 `ClientSession` 列表方法移除；超时改为 **float 秒**。

## 三、命名风格变化：camelCase → snake_case

**线缆上仍然是 camelCase**（协议 JSON 没变）；变的是 **Python 侧属性名**。
自己 `model_dump()` 时如果下游要协议格式，记得 `by_alias=True`。

| v1（Python 属性） | v2（Python 属性） |
| --- | --- |
| `isError` | `is_error` |
| `inputSchema` | `input_schema` |
| `outputSchema` | `output_schema` |
| `nextCursor` | `next_cursor` |
| `mimeType` | `mime_type` |
| `structuredContent` | `structured_content` |
| `serverInfo` | `server_info` |
| `protocolVersion` | `protocol_version` |
| `uriTemplate` | `uri_template` |
| `listChanged` | `list_changed` |
| `progressToken` | `progress_token` |

实测手感（v2 正确写法）：

```python
(await client.list_tools()).tools[0].input_schema   # 不是 inputSchema

result = await client.call_tool("add", {"a": 1, "b": 2})
result.is_error                  # 不是 isError
result.structured_content        # 不是 structuredContent

(await client.read_resource("config://app")).contents[0].mime_type   # 不是 mimeType
(await client.list_tools()).next_cursor                              # 不是 nextCursor（None 即结束）
# 装饰器侧同理：@mcp.resource(..., mime_type=...)（v1 是 mimeType=）
```

## 四、错误类型变化

| | v1 | v2 |
| --- | --- | --- |
| 协议错误 | `McpError` | **`MCPError`**（`from mcp import MCPError`） |
| 构造方式 | 包一层 `ErrorData` | 直接 `(code, message, data)` |
| 工具业务错误 | `ToolError` | `ToolError`（**未变**，导入路径在 `mcp.server.mcpserver.exceptions`） |

```python
from mcp import MCPError
from mcp.server.mcpserver.exceptions import ToolError, ResourceError, ResourceNotFoundError
```

**`ToolError` 与 `MCPError` 的区别（最容易踩的一脚）**

| | `ToolError` | `MCPError` |
| --- | --- | --- |
| 在 tool 里抛出后 | 调用**正常返回**，`result.is_error=True` | 变成 **JSON-RPC error** |
| 模型能否看到消息 | **能** —— 文案在 `result.content` 里 | **不能** |
| 客户端表现 | `call_tool` 不抛异常 | `Client` 抛 `MCPError` |
| 用途 | 业务失败（"没这本书"） | 协议级失败（参数非法、方法不存在） |

> 经验法则：**想让模型自己纠错 → `raise ToolError(...)`；想让宿主/日志炸掉 → `raise MCPError(...)`。** 未知工具同样是 `is_error=True` + `Unknown tool: ...`，调用本身不抛。

## 五、协议版本常量变化

v1 → v2 的**头号静默变更**：`LATEST_PROTOCOL_VERSION` 从 `"2025-11-25"` 变成 **`"2026-07-28"`**。

```python
# v1 —— 该模块已删除
from mcp.shared.version import LATEST_PROTOCOL_VERSION
```

```python
# v2 —— mcp.types.version 是 mcp_types.version 的镜像（同一对象）
from mcp.types.version import (
    LATEST_PROTOCOL_VERSION, KNOWN_PROTOCOL_VERSIONS, HANDSHAKE_PROTOCOL_VERSIONS,
    MODERN_PROTOCOL_VERSIONS, LATEST_HANDSHAKE_VERSION, LATEST_MODERN_VERSION,
    OLDEST_SUPPORTED_VERSION, is_version_at_least,
)
```

常量逐字（API reference）：

```python
KNOWN_PROTOCOL_VERSIONS: Final[tuple[str, ...]] = (
    "2024-11-05", "2025-03-26", "2025-06-18", "2025-11-25", "2026-07-28",
)
HANDSHAKE_PROTOCOL_VERSIONS: Final[tuple[str, ...]] = (
    "2024-11-05", "2025-03-26", "2025-06-18", "2025-11-25",
)
MODERN_PROTOCOL_VERSIONS: Final[tuple[str, ...]] = ("2026-07-28",)

SUPPORTED_PROTOCOL_VERSIONS: tuple[str, ...] = (*HANDSHAKE_PROTOCOL_VERSIONS, *MODERN_PROTOCOL_VERSIONS)

LATEST_PROTOCOL_VERSION: Final[str] = KNOWN_PROTOCOL_VERSIONS[-1]              # "2026-07-28"
LATEST_HANDSHAKE_VERSION: Final[str] = HANDSHAKE_PROTOCOL_VERSIONS[-1]        # "2025-11-25"
LATEST_MODERN_VERSION: Final[str] = MODERN_PROTOCOL_VERSIONS[-1]              # "2026-07-28"
OLDEST_SUPPORTED_VERSION: Final[str] = HANDSHAKE_PROTOCOL_VERSIONS[0]         # "2024-11-05"

def is_version_at_least(version: str, minimum: str) -> bool:
    """Return True if `version` is a known revision at least as new as `minimum`."""
```

要点：

| 常量 | 含义 |
| --- | --- |
| `KNOWN_PROTOCOL_VERSIONS` | 我认识的**全部**修订（含现代版） |
| `HANDSHAKE_PROTOCOL_VERSIONS` | 可以走 **initialize 握手**协商的旧版本 |
| `MODERN_PROTOCOL_VERSIONS` | **现代**版本（`server/discover` 路线） |
| `LATEST_HANDSHAKE_VERSION` | 握手路线的天花板 `"2025-11-25"` |
| `LATEST_MODERN_VERSION` | 现代路线的最新 `"2026-07-28"` |
| `OLDEST_SUPPORTED_VERSION` | 最老的兼容版 `"2024-11-05"` |
| `is_version_at_least()` | 版本比较（比字符串比大小安全） |

⚠️ **三个坑**：
1. `LATEST_PROTOCOL_VERSION` 是 **`"2026-07-28"`，initialize 握手无法协商它** —— 别拿它当握手的期望值，握手要用 `LATEST_HANDSHAKE_VERSION`。
2. 这些 tuple 真的是 **tuple**（v1 的 `SUPPORTED_PROTOCOL_VERSIONS` 是 list），与 list 拼接会 `TypeError`。想拼列表就 `[*KNOWN_PROTOCOL_VERSIONS]`。
3. `SUPPORTED_PROTOCOL_VERSIONS` 在 v2 **已废弃**（虽仍存在）。

其他 meta key 常量（`mcp_types` 顶层）：`PROTOCOL_VERSION_META_KEY`、`CLIENT_INFO_META_KEY`、`CLIENT_CAPABILITIES_META_KEY`、`SERVER_INFO_META_KEY`、`LOG_LEVEL_META_KEY`、`CORE_RESULT_TYPES`、`DEFAULT_NEGOTIATED_VERSION`。

## 七、自测

**1. 你把老项目依赖锁成 `mcp>=1.28,<2`，同事不解。请用一句话解释这个上界为什么存在。**

**2. 下面这段 v1 代码在 v2 下会依次报哪两个错？给出修好后的完整两行。**

```python
from mcp.server.fastmcp import FastMCP
mcp = FastMCP("Demo", port=9000)
```

**3. 你的 tool 里 `raise MCPError(...)`，期望模型看到"参数不对，请改用 X"。为什么模型看不到？应该改成什么？**

**4. 为什么不能写 `if client.protocol_version == LATEST_PROTOCOL_VERSION` 来判断"对方支持现代协议"？正确写法是什么？**

---

### 答案

**1.** 因为 `pip install mcp` 现在装的就是 2.x：`<2` 上界能防止依赖解析在未迁移时把你从 1.x 拉到 2.x（`FastMCP` 直接消失）。官方原文："Since `pip install mcp` now installs 2.x, keep a `<2` upper bound on your requirement (for example `mcp>=1.28,<2`) until you've migrated."

**2.** 第一个错 `ModuleNotFoundError: No module named 'mcp.server.fastmcp'`（旧路径已删除）；改成 `from mcp.server import MCPServer` 后，第二个错 `TypeError: MCPServer.__init__() got an unexpected keyword argument 'port'`（transport 参数不在构造器）：

```python
from mcp.server import MCPServer
mcp = MCPServer("Demo")            # 端口改到 mcp.run(transport="streamable-http", port=9000)
```

**3.** 因为 `MCPError` 是**协议级**错误，会被转成 JSON-RPC error —— 客户端 `call_tool` 直接抛 `MCPError`，消息不进 `result.content`，模型拿不到文案。改成 `raise ToolError("参数不对，请改用 X")`：调用**正常返回** `is_error=True`，消息在 `result.content` 里供模型读取（见第四节表格）。

**4.** 因为 `LATEST_PROTOCOL_VERSION` 是 `"2026-07-28"`，而它**无法通过 initialize 握手协商** —— 用握手连上的客户端 `protocol_version` 永远不等于它，判断恒假。正确做法：用 `is_version_at_least(client.protocol_version, LATEST_MODERN_VERSION)` 判断现代（`2026-07-28`）语义，或看 `MODERN_PROTOCOL_VERSIONS` 成员关系；握手天花板是 `LATEST_HANDSHAKE_VERSION`（`"2025-11-25"`）。
