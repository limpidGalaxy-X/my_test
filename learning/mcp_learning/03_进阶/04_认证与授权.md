# 04 · 认证与授权（OAuth 2.1）

> 本文所有 SDK API 均来自 `参考_MCP_Python_SDK_v2速查表.md`（`mcp` **2.2.0**）。
> 标注 **UNVERIFIED** 的地方，速查表本身也没有逐字核实 —— 不要照着它写生产代码。
> 没有鉴权需求的本地 stdio 服务器可以整篇跳过：**stdio 不过鉴权层**。

---

## 一、为什么 MCP 用 OAuth 2.1

MCP 的鉴权是**传输层**能力，只在 HTTP 类传输上生效（规范原文：Authorization 对实现是 **OPTIONAL**；用 HTTP 传输的 **SHOULD** 遵循，用 stdio 的 **SHOULD NOT** 走这套，而是从环境变量拿凭据）。

两个角色（**不是**传统的"授权服务器 + 资源服务器 + 客户端"三分法，MCP server 自己只当资源服务器）：

| MCP 角色 | OAuth 2.1 角色 | 干什么 |
| --- | --- | --- |
| **MCP server** | OAuth 2.1 **resource server** | **只验证** token，**不签发** token |
| MCP client | OAuth 2.1 **client** | 发现 AS、走授权码流程、拿 token、带给 server |

> 速查表原文的措辞就是「**服务器 = OAuth 2.1 resource server（只验证、不签发）**」。所以你在 `MCPServer(...)` 里交出去的是一个 **`TokenVerifier`**（自己实现的校验函数），而不是一个完整的授权服务器。速查表另提一句：还有过时参数 `auth_server_provider=`（内嵌完整 AS），**新服务器不建议用**。

依赖的标准（规范原文列举的 subset）：

| 标准 | 作用 |
| --- | --- |
| OAuth 2.1 IETF DRAFT | 基础流程（授权码 + PKCE 为唯一推荐形态） |
| RFC 8414 | OAuth 2.0 Authorization Server Metadata（`/.well-known/oauth-authorization-server`） |
| RFC 7591 | OAuth 2.0 Dynamic Client Registration（客户端动态注册） |
| RFC 9728 | OAuth 2.0 Protected Resource Metadata（`/.well-known/oauth-protected-resource`，**速查表明确写到这个路径**） |
| RFC 8707 | Resource Indicators（`resource` 参数，防 token 混用） |

> 前四项在 MCP 规范 2025-06-18 authorization 页的 "Standards Compliance" 里逐条列出（OAuth 2.1 draft 具体版本为 `draft-ietf-oauth-v2-1-13`）；RFC 8707 对应规范里的 "Resource Parameter Implementation" 一节。

## 二、发现流程时序图

核心机制：**客户端先撞一次墙，从 401 的 `WWW-Authenticate` 里学到去哪儿授权。**

```
MCP Client                                          MCP Server (= resource server)
    │                                                        │
    │  ① POST /mcp   (tools/call, 无 Authorization)          │
    ├───────────────────────────────────────────────────────>│
    │                                                        │  无有效 token
    │  ② 401 Unauthorized                                    │
    │     WWW-Authenticate: Bearer                           │
    │       resource_metadata="http://…/.well-known/         │
    │                           oauth-protected-resource/mcp"│
    │<───────────────────────────────────────────────────────┤
    │                                                        │
    │  ③ GET /.well-known/oauth-protected-resource/mcp      │
    ├───────────────────────────────────────────────────────>│
    │     { "resource": "http://…/mcp",                      │
    │       "authorization_servers": ["https://auth.example.com"],
    │       "scopes_supported": ["notes:read"] }             │
    │<───────────────────────────────────────────────────────┤
    │                                                        │
    │  ④ GET https://auth.example.com/.well-known/           │
    │         oauth-authorization-server      (RFC 8414)     │
    ├───────────────────────────────────────────────────────>│   (打到 AS，不是 MCP server)
    │     { "issuer": ..., "authorization_endpoint": ...,    │
    │       "token_endpoint": ..., "registration_endpoint": …}│
    │<───────────────────────────────────────────────────────┤
    │                                                        │
    │  ⑤ (可选) 动态注册 POST registration_endpoint (RFC 7591)│
    │                                                        │
    │  ⑥ 授权码 + PKCE：浏览器打开 authorization_endpoint     │
    │     ?response_type=code&code_challenge=…&              │
    │      resource=http://…/mcp        ← RFC 8707 必须带     │
    │     → 回调拿到 code → POST token_endpoint + code_verifier│
    │     → access_token                                     │
    │                                                        │
    │  ⑦ POST /mcp   Authorization: Bearer <access_token>    │
    ├───────────────────────────────────────────────────────>│
    │                                                        │  TokenVerifier.verify_token()
    │  ⑧ 200 OK  (正常 JSON-RPC 结果)                         │  → 校验 audience / scopes
    │<───────────────────────────────────────────────────────┤
```

> ③ 的路径形态来自速查表：「应用路由：`/mcp` 与 `/.well-known/oauth-protected-resource/mcp`（RFC 9728）」。
> ④～⑥ 的报文细节属于 OAuth/RFC 标准本身，速查表未逐字收录（**字段级细节请查各 RFC 原文**）。
> 关键点：**③④ 两步都是无 token 的公开端点**，所以"发现"必须在鉴权之前完成。

## 三、服务端：`TokenVerifier` + `AuthSettings`

### 3.1 最小可用示例（逐字来自速查表）

```python
from pydantic import AnyHttpUrl
from mcp.server import MCPServer
from mcp.server.auth.provider import AccessToken, TokenVerifier
from mcp.server.auth.settings import AuthSettings

RESOURCE = "http://127.0.0.1:8000/mcp"
KNOWN_TOKENS = {
    "alice-token": AccessToken(token="alice-token", client_id="alice", scopes=["notes:read"], resource=RESOURCE),
}

class StaticTokenVerifier(TokenVerifier):
    async def verify_token(self, token: str) -> AccessToken | None:
        return KNOWN_TOKENS.get(token)

mcp = MCPServer(
    "Notes",
    token_verifier=StaticTokenVerifier(),
    auth=AuthSettings(
        issuer_url=AnyHttpUrl("https://auth.example.com"),
        resource_server_url=AnyHttpUrl(RESOURCE),
        required_scopes=["notes:read"],
        validate_token_resource=True,
    ),
)
```

### 3.2 一个更完整的（可读）示例

> 说明：下面把上面的骨架扩成一个"能看懂流程"的版本，**不要求运行**；只用速查表出现过的名字（`MCPServer`、`TokenVerifier`、`AccessToken`、`AuthSettings`、`get_access_token`、`ToolError`），JWT 解析部分用注释代替具体库调用，避免引入未核实 API。

```python
"""auth_server.py — MCP server 作为 OAuth 2.1 resource server（示意，未运行验证）。"""
from pydantic import AnyHttpUrl
from mcp.server import MCPServer
from mcp.server.auth.provider import AccessToken, TokenVerifier
from mcp.server.auth.settings import AuthSettings
from mcp.server.auth.middleware.auth_context import get_access_token
from mcp.server.mcpserver.exceptions import ToolError

RESOURCE = "http://127.0.0.1:8000/mcp"          # 必须与客户端实际访问的 URL 一致
ISSUER = "https://auth.example.com"
REQUIRED_SCOPES = ["notes:read"]


class JwtTokenVerifier(TokenVerifier):
    """只做验证：签名 / 过期 / issuer / **audience** / scopes。"""

    def __init__(self, issuer: str, audience: str) -> None:
        self.issuer = issuer
        self.audience = audience

    async def verify_token(self, token: str) -> AccessToken | None:
        # 真实实现里用 pyjwt[crypto] 验签并校验 claims，顺序不能省：
        #   1) 验签名（JWKS 来自 issuer 的 jwks_uri）  2) 验 exp / nbf
        #   3) claims["iss"] == self.issuer            4) claims["aud"] == self.audience  ← RFC 8707 关键
        #   5) scopes = claims["scope"].split()
        # 任何一步不通过就 return None（→ 401），不要 return 一个"空权限"对象。
        try:
            claims = decode_and_validate(token, self.issuer, self.audience)   # 你自己接的库（占位符）
        except Exception:
            return None
        if "notes:read" not in claims.get("scope", "").split():
            return None
        return AccessToken(
            token=token, client_id=claims["client_id"], scopes=claims["scope"].split(),
            resource=self.audience, subject=claims.get("sub"), expires_at=claims.get("exp"),
            claims=claims,
        )


mcp = MCPServer(
    "Notes",
    instructions="Read notes for the signed-in user.",
    token_verifier=JwtTokenVerifier(issuer=ISSUER, audience=RESOURCE),
    auth=AuthSettings(
        issuer_url=AnyHttpUrl(ISSUER),
        resource_server_url=AnyHttpUrl(RESOURCE),
        required_scopes=REQUIRED_SCOPES,
        validate_token_resource=True,             # 见下方"红线"
    ),
)


@mcp.tool()
def delete_note(note_id: str) -> str:
    """Delete one note (requires notes:read)."""
    identity = get_access_token()                 # → AccessToken | None
    if identity is None:                          # 正常 HTTP 流程走不到这里（中间件已拦住）
        raise ToolError("no access token on this connection")
    if "notes:read" not in identity.scopes:
        raise ToolError("missing scope: notes:read")
    return f"deleted {note_id!r} by {identity.subject} (client={identity.client_id})"


if __name__ == "__main__":
    mcp.run(transport="streamable-http", port=8000)   # 路由 /mcp
```

⚠️ 上面 `decode_and_validate(...)` 是你自己接的 JWT 库调用，**速查表未收录该 API**，属于占位符。

### 3.3 `AuthSettings` 四个字段

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `issuer_url` | `AnyHttpUrl` | **授权服务器（AS）的 issuer**。server 会把它公布给客户端，并用于校验 token 的 `iss` |
| `resource_server_url` | `AnyHttpUrl` | 本 server 自己的 URL（即 RFC 9728 里的 `resource`），**必须与客户端访问的 URL 一致** |
| `required_scopes` | `list[str]` | 访问所需 scope；缺 scope → 403 |
| `validate_token_resource` | `bool` | 是否校验 token 的 `resource`（audience）与本 server 匹配 |

> 速查表的原文警告：`validate_token_resource` **不设时会发 `MCPDeprecationWarning`，且行为等同 `False`**；**3.0 起在有 `resource_server_url` 时默认 `True`**。也就是说：**现在不写它，你的服务器当前不校验 audience** —— 这是一个隐蔽的安全缺口。显式写 `True`。

### 3.4 `TokenVerifier` 与 `AccessToken`

```python
class TokenVerifier:
    async def verify_token(self, token: str) -> AccessToken | None: ...
```

- `TokenVerifier` **只有一个 async 方法**：`verify_token`。
- 返回 `None` = token 无效（→ 401）；返回 `AccessToken` = 通过。
- `AccessToken` 的字段：`token`、`client_id`、`scopes`、`resource`（**还有** `subject`、`expires_at`、`claims`）。
- `issuer_url` 不会自动传给 verifier —— 你的 verifier 需要 issuer/audience 时用**闭包或构造参数**带进去。

### 3.5 ⚠️ `token_verifier=` 与 `auth=` 必须成对

> 速查表原文：「`token_verifier=` 与 `auth=` **必须成对出现**，否则构造时 `ValueError`。」

```python
MCPServer("Notes", token_verifier=StaticTokenVerifier())     # ❌ ValueError
MCPServer("Notes", auth=AuthSettings(...))                   # ❌ ValueError
MCPServer("Notes", token_verifier=StaticTokenVerifier(), auth=AuthSettings(...))   # ✅
```

这是**构造期**错误（不是运行期），所以哪怕你只是想本地跑一下也会立刻炸 —— 报错点在 `MCPServer(...)` 那一行，别去翻中间件。

## 四、在 handler 里取身份

```python
from mcp.server.auth.middleware.auth_context import get_access_token

@mcp.tool()
def whoami() -> str:
    identity = get_access_token()      # → AccessToken | None
    if identity is None:
        return "anonymous"
    return f"{identity.subject} via {identity.client_id}, scopes={identity.scopes}"
```

> **速查表划线重点**：「stdio 与内存 `Client(mcp)` **不过鉴权层**」。
> 这意味着：
>
> | 连接方式 | `get_access_token()` |
> | --- | --- |
> | Streamable HTTP + 有效 Bearer | `AccessToken` |
> | Streamable HTTP 无 token | 请求已被 401 拦住，进不了 handler |
> | **stdio**（`mcp.run()` 默认） | **恒为 `None`** |
> | **内存**（`Client(mcp)`） | **恒为 `None`** |
>
> 实践后果：**你的单元测试永远测不到鉴权分支**（`Client(mcp)` 不经过鉴权层）。
> 想测鉴权，必须起真实 HTTP 传输并手工带 header。
> 另外，handler 里必须把 `None` 当合法情况处理，否则本地开发时全是 `AttributeError: 'NoneType' ...`。

## 五、路由形态与状态码

| 项 | 值 |
| --- | --- |
| MCP 端点 | **`/mcp`** |
| RFC 9728 元数据端点 | **`/.well-known/oauth-protected-resource/mcp`** |
| 未认证响应 | **401** + `WWW-Authenticate: Bearer ... resource_metadata="..."` |
| AS 元数据端点（在 AS 上） | `/.well-known/oauth-authorization-server`（RFC 8414） |

状态码含义（**401 / 403 / 400**）：

| 状态码 | 含义 | 你该做什么 |
| --- | --- | --- |
| **401 Unauthorized** | 没有凭据，或凭据无效（你的 `verify_token` 返回了 `None`） | 客户端按 `WWW-Authenticate` 里的 `resource_metadata` 去发现 AS、走授权流程；**不要盲目重试同一个 token** |
| **403 Forbidden** | 身份认得出来，但**权限不够**（缺 `required_scopes` 里的 scope） | 重新授权并申请缺失的 scope；服务端日志里应能看到缺哪个 scope |
| **400 Bad Request** | 请求本身不合法（畸形报文、协议版本头不匹配等）。**注意：400 与鉴权无关** | 检查 JSON-RPC 报文与 `Mcp-Protocol-Version` 等协议头，不要往 token 上找原因 |

> 排错口诀：**401 = 你是谁？403 = 你不能。400 = 你说的话我听不懂。**
> 三者混在一起查，是新手最常见的半小时间浪费。

## 六、客户端侧

速查表给出的客户端变化清单（逐条）：

| 项 | 说明 |
| --- | --- |
| Provider 基类 | `OAuthClientProvider` / `ClientCredentialsOAuthProvider` / `PrivateKeyJWTOAuthProvider` / `IdentityAssertionOAuthProvider` 现在都**继承 `httpx2.Auth`** |
| 挂载方式 | `httpx2.AsyncClient(auth=provider)` |
| 参数改名 | **`scopes=` → `scope=`** |
| 回调 | `callback_handler` 现在返回 **`AuthorizationCodeResult`** |
| 删除 | `RFC7523OAuthClientProvider` 与 `JWTParameters` **已删除** |
| 删除 | `OAuthClientProvider` 的 `timeout` 参数**被移除** |

标准用法骨架：

```python
import httpx2
from mcp import Client
from mcp.client.streamable_http import streamable_http_client

# provider 继承 httpx2.Auth —— 也就是说它自己负责往请求上加 Authorization 头、
# 在 401 时触发授权码流程、缓存/刷新 token。
async with httpx2.AsyncClient(auth=provider) as http_client:
    transport = streamable_http_client("http://localhost:8000/mcp", http_client=http_client)
    async with Client(transport) as client:
        result = await client.list_tools()
        print([tool.name for tool in result.tools])
```

> ⚠️ `streamable_http_client` 的参数**只有** `url`、`http_client`、`terminate_on_close`。
> 所以**鉴权必须挂在 `httpx2.AsyncClient` 上**；写 `streamable_http_client(url, headers={...})` 会
> `TypeError: streamable_http_client() got an unexpected keyword argument 'headers'`。
> 想手动带一个静态 Bearer token（调试常用）也是同一个位置：
>
> ```python
> async with httpx2.AsyncClient(headers={"Authorization": "Bearer alice-token"}) as http_client:
>     ...
> ```
>
> `provider` 的**构造参数**（client_id / redirect_uri / `scope=` / 回调等）速查表未逐字收录，**UNVERIFIED** —— 以你所装版本的 API reference 为准。

## 七、安全红线（每条都是真实会被打穿的洞）

**① token 透传禁令（confused deputy）**
- server **绝不能**拿客户端给的 token 去调**下游别的服务**再原样透传；也不要把 token 抄进日志、错误消息、tool 返回内容。
- 原因：token 的 audience 是**你**，不是下游。透传等于把"别人给你的钥匙"递给第三方。

**② audience 校验（RFC 8707）**
- 必须开 `validate_token_resource=True`，且 `verify_token` 里自己比对 `aud`。
- 不校验的后果：**发给 A 服务器的 token 能拿来打 B 服务器**（同一 AS 下的横向越权）。
- 速查表提醒：不设该参数时行为等同 `False` 且发 `MCPDeprecationWarning` —— 别依赖默认值。

**③ PKCE 必须实现**
- 授权码流程**必须**带 PKCE（OAuth 2.1 的硬要求）。公共客户端（桌面 Host、CLI）没有 client secret，PKCE 是唯一防线。
- 少了它，授权码可被同机/同网段的攻击者截获换取 token。

**④ `resource` 参数必须带**
- 授权请求里要带 `resource=<你的 MCP server URL>`（RFC 8707）。客户端侧 provider 应自动带；如果你自己拼授权 URL，**别漏**。
- 漏了的后果：AS 签出的 token 没有明确 audience → ② 的校验无从谈起。

**⑤ `@mcp.custom_route` 注册的端点永不鉴权**
- 速查表原文：`@mcp.custom_route("/health", methods=["GET"])`（**永不鉴权**）。
- 所以：**不要**在 `custom_route` 上暴露任何用户数据、内部状态、调试信息、管理操作。
  它适合放 `/health`、`/robots.txt` 这种完全公开的东西。

**⑥ HTTP 传输必须配 `TransportSecuritySettings`（否则 421）**
- 速查表原文：默认只接受 localhost（DNS-rebinding 防护）；部署到真实域名必须传
  `transport_security=TransportSecuritySettings(allowed_hosts=[...], allowed_origins=[...])`，
  否则全部 **`421 Misdirected Request`**。
- 这条**不是鉴权**但和鉴权一样容易让你"上生产就全挂"：本地怎么测都过，域名一换全 421。
- 验证方式：`mcp.run(transport="streamable-http", host="0.0.0.0", port=8000, transport_security=transport_security)`
  —— `transport_security` 是 `run()` 的合法参数（transport 参数都在 `run()` / `*_app()` 上）。

**⑦ HTTPS 与 CORS**
- 生产必须 HTTPS（token 是 bearer）；CORS `allow_headers` 需含 `Authorization`、`Content-Type`、
  `Last-Event-ID`、`Mcp-Method`、`Mcp-Name`、`Mcp-Protocol-Version`、`Mcp-Session-Id`，
  `expose_headers=["Mcp-Session-Id"]` —— 少一个 header，浏览器端 Host 就会静默失败。

## 八、自测

**1. 你的 MCP server 里 `verify_token` 返回了合法 `AccessToken`，但客户端拿到的响应是 403。最可能是什么原因？**

**2. 同事说"我本地用 `Client(mcp)` 测了，`get_access_token()` 返回 `None`，所以鉴权代码写错了"。请指出他的判断错在哪，以及正确的验证方式。**

**3. 你把 MCP server 从 `127.0.0.1:8000` 部署到 `mcp.example.com`，所有请求都返回 421，token 完全没问题。给出原因和一个修复方向。**

**4. 为什么 MCP 的 `MCPServer` 需要 `token_verifier` 和 `auth` 同时提供？只给一个会发生什么、什么时候发生？**

---

### 答案

**1.** `401` 是"没凭据/凭据无效"，`403` 是"身份有效但**权限不够**"。`verify_token` 返回了 `AccessToken` 说明身份已经通过，
所以问题在**授权**：通常是 token 的 `scopes` 不包含 `AuthSettings(required_scopes=[...])` 里要求的 scope（也可能是你在 handler 里自己检查 scope 后拒绝）。
查法：对比 `required_scopes` 与 token 实际 scope；必要时让客户端用 `scope=` 重新授权申请缺失的 scope。

**2.** 他错在把"没经过鉴权层"当成了 bug。速查表明确写着：**stdio 与内存 `Client(mcp)` 不过鉴权层**，
这两条路径上 `get_access_token()` **恒为 `None`**，这是设计如此，不是代码错误。
正确做法：用真实 HTTP 传输（`mcp.run(transport="streamable-http", port=8000)` 或 `streamable_http_app()`），
客户端用 `httpx2.AsyncClient(headers={"Authorization": "Bearer <token>"})` 或挂 `OAuthClientProvider`，再断言
`get_access_token()` 返回 `AccessToken`；同时要保留"`None` 是合法输入"的分支，避免本地开发时 `AttributeError`。

**3.** 原因不是鉴权，是**传输安全（DNS-rebinding 防护）**：默认只接受 localhost，域名一换就全部
**`421 Misdirected Request`**。修复：给 `run()` / `streamable_http_app()` 传
`transport_security=TransportSecuritySettings(allowed_hosts=["mcp.example.com"], allowed_origins=["https://mcp.example.com"])`
（同时确认 `resource_server_url` 等 URL 也已从 `127.0.0.1` 改成真实域名，否则换来 401/403）。

**4.** 因为 MCP server 是 **OAuth 2.1 resource server，只验证不签发**：`token_verifier` 回答"这个 token 有效吗"，
`auth`（`AuthSettings`）回答"我的 issuer / resource / 需要哪些 scope、要不要校验 audience"，
两者是同一套鉴权中间件的两半。速查表原文：**必须成对出现，否则构造时 `ValueError`** ——
报错发生在 `MCPServer(...)` 那一行（**构造期**，不是运行期），所以少写一个的表现是"服务器根本建不起来"。
样例：`MCPServer("Notes", token_verifier=StaticTokenVerifier(), auth=AuthSettings(issuer_url=..., resource_server_url=..., required_scopes=[...], validate_token_resource=True))`。
