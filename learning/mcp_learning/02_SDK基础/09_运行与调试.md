# 09 · 运行与调试

> 代码写完了，下一步是"让它跑起来、让别人能用"。
> 本篇覆盖：三种运行方式、命令行工具、Inspector、接入真实 Host、以及 12 个高频报错。

---

## 一、三种运行方式

### 1. 内存连接（开发自测，强烈推荐先用这个）

```python
from mcp import Client
from your_server import mcp

async with Client(mcp) as client:
    print(await client.call_tool("add", {"a": 1, "b": 2}))
```

- 不启动进程、不开端口、不经过传输层
- 出问题一定是**你的业务代码或注册代码**的问题，排查范围最小
- 官方 SDK 自己的测试就是这么做的
- ⚠️ 不支持服务端反向请求（elicitation / roots / sampling），会报
  `NoBackChannelError`

### 2. stdio（给本机 Host 用）

```powershell
python server.py            # 前提：文件里写了 if __name__ == "__main__": mcp.run()
# 或者不写 main 也能跑：
.\.venv\Scripts\python.exe -m mcp run server.py
```

- Host 会把这个进程当子进程启动，通过 stdin/stdout 收发 JSON-RPC
- **stdout 是协议通道**：绝不能 `print()`，日志必须走 stderr
- 直接运行会"卡住"——它在等 Host 发报文，这是正常的

### 3. Streamable HTTP（部署给远程/多客户端用）

```powershell
.\.venv\Scripts\python.exe -m mcp run server.py --transport streamable-http
# 默认监听 http://127.0.0.1:8000/mcp
```

也可以写在文件里：

```python
if __name__ == "__main__":
    mcp.run(transport="streamable-http", host="127.0.0.1", port=8000)
```

常用参数（`run()` 的 kwargs）：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `host` | `127.0.0.1` | 只绑本机，别随手改成 `0.0.0.0` |
| `port` | `8000` | 端口 |
| `streamable_http_path` | `/mcp` | 端点路径 |
| `json_response` | `False` | 是否用普通 JSON 而非 SSE 流 |
| `stateless_http` | `False` | 无状态模式 |

> ⚠️ `MCPServer("x", port=9000)` 会直接报
> `TypeError: MCPServer.__init__() got an unexpected keyword argument 'port'`。
> **传输参数不在构造函数里**，只在 `run()` / `*_app()` 里。

## 二、命令行工具 `mcp`（需要 `mcp[cli]`）

```powershell
# 用 MCP Inspector 打开服务器（图形界面，能点着调工具）
.\.venv\Scripts\python.exe -m mcp dev server.py
.\.venv\Scripts\python.exe -m mcp dev server.py --with pandas --with numpy

# 运行服务器
.\.venv\Scripts\python.exe -m mcp run server.py
.\.venv\Scripts\python.exe -m mcp run server.py:my_server      # 对象名不是 mcp/server/app 时
.\.venv\Scripts\python.exe -m mcp run server.py --transport streamable-http

# 装进 Claude Desktop 配置（仅 Claude Desktop）
.\.venv\Scripts\python.exe -m mcp install server.py --name "My Server" -v API_KEY=abc123

# 版本
.\.venv\Scripts\python.exe -m mcp version
```

几个要点：

- `mcp dev` 需要 **Node.js**（它会用 `npx` 拉起 Inspector）。没装 Node 就用内存自测代替。
- `mcp run` **不会**执行你文件里的 `if __name__ == "__main__":` 块，它自己找模块级的
  `mcp` / `server` / `app` 变量并调用 `run()`。
- `mcp run` / `mcp dev` **只识别 `MCPServer`**（低层 `Server` 得自己起）。

## 三、接进真实 Host

以 Claude Desktop 为例，它的配置文件里长这样：

```json
{
  "mcpServers": {
    "my-server": {
      "command": "E:\\PyTest\\.venv\\Scripts\\python.exe",
      "args": ["E:\\PyTest\\mcp_learning\\04_实战项目\\server.py"]
    }
  }
}
```

注意事项：

1. **必须写解释器的绝对路径**，Host 不会用你的 venv
2. 服务器文件要能被直接执行（有 `if __name__ == "__main__": mcp.run()`，或者靠 Host 传 stdio）
3. 工作目录不确定 → 代码里不要在 import 时读相对路径文件
4. 改完配置要**重启 Host**
5. 出问题先看 Host 的日志（它的 stderr 面板 / 日志文件）

## 四、手工调试 HTTP：直接用 JSON-RPC 打过去

想确认"到底是协议层还是我的代码有问题"，可以绕过 SDK：

```powershell
curl.exe -s http://127.0.0.1:8000/mcp `
  -H "Content-Type: application/json" `
  -H "Accept: application/json, text/event-stream" `
  -H "MCP-Protocol-Version: 2026-07-28" `
  -d '{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"tools/list\",\"params\":{}}'
```

能拿到工具列表 → 服务器没问题，是客户端的事；拿不到 → 服务器/传输层的事。

## 五、高频报错速查

| 报错 | 原因 | 解决 |
| --- | --- | --- |
| `ModuleNotFoundError: No module named 'mcp.server.fastmcp'` | 代码是 v1 写法，装的是 v2 | 改用 `from mcp.server import MCPServer`，详见 `../03_进阶/05_v1到v2迁移对照.md` |
| `ImportError: cannot import name 'FastMCP'` | 同上 | 同上 |
| `No module named 'mcp'` | 用错解释器 | 显式用 `.\.venv\Scripts\python.exe` |
| `InvalidSignature: Unable to evaluate type annotations for callable 'x'` | 开了 `from __future__ import annotations`，但注解里的名字没 import 进来 | 把 `Context` 等类型 import 到模块顶层 |
| `ValueError: Mismatch between URI parameters {...} and function parameters {...}` | 资源模板占位符名和函数参数名不一致 | 改成同名 |
| 静态资源带参数报错 | `@mcp.resource("a://b")` 的函数不能有参数 | 要么去掉参数，要么把 URI 改成模板 |
| `Context is not available outside of a request` | 在 helper 函数里用了 `Context`，或给 resource/prompt 的 Context 加了泛型 | 手动把 ctx 传进 helper；resource/prompt 只写裸 `Context` |
| `TypeError: MCPServer.__init__() got an unexpected keyword argument 'port'` | 传输参数写到了构造函数 | 挪到 `mcp.run(...)` |
| `RuntimeError: Client must be used within an async context manager` | 没进 `async with` 就用了 client | 用 `async with Client(...) as c:` |
| `RuntimeError: Task group is not initialized. Make sure to use run().` | ASGI 挂载时宿主没启动 session manager | `async with mcp.session_manager.run():` |
| `NoBackChannelError: ... no back-channel for server-initiated requests` | 用内存连接或现代协议调用了 elicitation/roots/sampling | 换 stdio/HTTP，并加 `mode="legacy"` |
| `TypeError: 'NoneType' object can't be awaited`（进度回调） | `progress_callback` 写成了同步函数 | 改成 `async def` |
| 客户端调用报 `MCPError: Internal server error` | 服务端 handler 抛了异常 | **去看服务端 stderr 日志**，真实原因在那里 |
| 日志里 `ValueError: Missing required arguments: {'code'}` | prompt 缺必填参数 | 客户端补齐参数 |
| `421 Misdirected Request` | HTTP 传输的 Host/Origin 校验失败 | 传 `transport_security=TransportSecuritySettings(allowed_hosts=[...], allowed_origins=[...])` |
| `400 Bad Request` | `MCP-Protocol-Version` 头缺失或不支持 | 带上受支持的版本号 |
| 连接成功但 `tools/list` 空 | 工具定义文件没被执行到 / 装饰器被跳过 | 确认没有把注册写在 `if __name__` 里面 |
| stdio 下 Host 报 JSON 解析失败 | 你往 stdout `print()` 了 | 全部改成 `logging`（走 stderr） |

## 六、日志怎么打

```python
import logging

logger = logging.getLogger(__name__)

@mcp.tool()
def do_work(x: int) -> int:
    logger.info("do_work x=%s", x)      # ✅ 走 stderr
    # print("do_work", x)               # ❌ 污染 stdout，stdio 模式下直接崩
    return x * 2
```

- `MCPServer(..., log_level="DEBUG")` 会调用 `logging.basicConfig()` 打开 SDK 自己的日志
- SDK 内部的错误日志非常有用：`Tool 'x' failed: ...`、`Tool 'x' rejected arguments: [...]`
  都是排错的第一手线索
- `ctx.info()` / `ctx.debug()` / `ctx.warning()` **已废弃**，别再用

## 七、调试检查清单

遇到问题按顺序问自己：

1. 用**内存 Client** 能跑通吗？不能 → 是业务/注册代码的问题
2. 装饰器生效了吗？`client.list_tools()` 里有它吗？
3. `input_schema` 对不对？参数名、类型、required 是否符合预期？
4. 是不是 `is_error=True` 而不是异常？看 `content[0].text` 的报错
5. 服务端 stderr 日志说了什么？
6. 传输层选对了吗？需要反向请求就必须用 stdio/HTTP + `mode="legacy"`
7. `mcp dev` + Inspector 里点一下试试（能排除客户端代码的干扰）

## 八、自测

1. 为什么 `python server.py` 之后终端"卡住"了？这是 bug 吗？
2. stdio 模式下为什么不能 `print()`？
3. `mcp run server.py` 和 `python server.py` 有什么区别？
4. 客户端收到 `MCPError: Internal server error`，第一步该做什么？
5. 什么时候必须把 Client 的 `mode` 设成 `"legacy"`？

<details>
<summary>参考答案</summary>

1. 不是 bug。服务器在 stdio 上等待 Host 发来的 JSON-RPC 报文，属于正常阻塞。
2. stdout 是 stdio 传输的协议通道，`print()` 会插进非协议内容，导致对端 JSON 解析失败。
3. `python server.py` 会执行你写的 `__main__` 块（通常直接 `mcp.run()`）；
   `mcp run` 不执行 `__main__`，而是自己找模块级 `mcp`/`server`/`app` 对象并调用 `run()`，
   还能通过 `--transport` 切换传输。
4. 去看**服务端**的 stderr 日志 —— 客户端看到的只是被抹平后的通用错误。
5. 需要服务端反向请求（elicitation / roots / sampling / `message_handler`）时。
   2026-07-28 版协议取消了服务端主动请求，SDK 的 `ctx.elicit` 仍走老路。

</details>
